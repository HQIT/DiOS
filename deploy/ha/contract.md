# 控制面 HA 隔离与持久契约

DiOS 控制面采用单活资源组。Infrastructure 确认旧节点失去执行和写入能力后，才将独占卷、控制服务和入口交给备用节点。任务、授权、预算和审计继续使用同一权威 Runtime 后端；业务应用通过既有 API 接入。

## 隔离对象与执行点

| 对象 | 强制条件 | 实现与证据 |
|---|---|---|
| 控制节点 | 备用卷挂载前获得旧主真实隔离成功回执；无多数或隔离失败时停止接管 | Pacemaker STONITH、`requires=fencing`、`no-quorum-policy=stop`；[三节点证据](../../docs/design/evidence/ha-live-20261126.json) |
| 卷和控制服务 | 单节点持有，卷→服务→VIP 启动，反序停止；停止失败隔离节点 | [原生配置](pacemaker.example.xml)与[停止超时实测](../../docs/design/evidence/ha-recovery-20261126.json) |
| 旧主重启 | 服务无开机启动入口，容器不自行重启，卷由集群独占管理 | [systemd unit](dios-control.service)、[Compose 覆盖](compose.ha.yaml)、旧主返回证据 |
| 旧 Worker/Attempt | Run、Attempt、Worker instance、lease epoch、授权代次匹配后才提交 | `RuntimeStore._owned`、`resolve_exit` 的数据库事务与 CAS；原任务恢复、撤权及过期所有者测试 |
| 授权、预算和审计 | 执行动作前持久提交；必要存储不可用时不签发有效执行权 | 原有 E2AG 控制点和权威事务；数据库断连与暂停场景 |
| 不确定工具结果 | 持久意图、回执和外部幂等/查询能力决定对账；未结清的调用阻止自动重放 | `tool_invocations.require_settled`，`faults.failed/ready`；既有未知工具结果回归 |
| 请求响应丢失 | 使用原幂等键查询/重提；保留原任务身份 | 数据库暂停期间提交超时，恢复后重复提交同一 Run，只有一次受理及执行 |

节点管理地址的业务端口由防火墙拒绝，只有 VIP 可访问。该入口限制与 STONITH 配合：撤下 VIP 负责流量切换，真实隔离负责阻止旧服务继续访问数据库、卷或外部端点。

## 故障模型与持久保证

| 故障 | 控制行为 | 数据恢复依据 |
|---|---|---|
| 单控制节点失联/暂停/停止失败 | 隔离旧主，再接管 | 共享权威数据库和持久卷保留已确认任务、授权、历史及产物 |
| 多数仲裁丢失 | 停止入口、服务和卷；不在少数分区接管 | 仲裁恢复后仍使用原有数据和任务身份 |
| 隔离设备不可达 | 保持备用资源停止；通道恢复后原生失败过期/重试 | 隔离完成前不放宽单写者条件 |
| 数据库断连 | 请求失败，Worker 保留现场并停止需持续授权的动作 | 数据库恢复后对账真实退出；完整结果优先恢复，允许重放的任务才获取新 Grant |
| 数据库暂停且 TCP 未断开 | 查询超时记录为观测未知；Worker 控制通道超时后受控停止 | 恢复后原 Run 对账；幂等提交不产生第二个逻辑任务 |
| 物理宿主、数据库副本、存储副本失效 | 按实际 Infrastructure 的同步复制、仲裁和隔离契约处理 | D01-3.02/.03 提供独立故障域与复制故障证据 |

容量契约固定企业档目标：已确认权威提交 RPO=0，单控制节点或数据库主节点故障 RTO≤5 分钟。试点档目标为 RPO≤15 分钟、RTO≤60 分钟。部署时将目标档位、允许故障集合、同步复制确认方式和恢复方式写入实际基础设施配置及交付记录；严格持久条件不满足时停止依赖该保证的新授权和外部动作。

当前实验为同一物理宿主上的三个控制节点、一个 PostgreSQL 实例和一个独占共享卷。控制节点失效后的已检查数据保持一致；物理宿主和数据副本丢失尚无资格结论。完整企业档接受以 D01-3.03 的数据库/卷复制、权限/预算/审计联合结果为依据。

PostgreSQL 服务须明确哪些故障下“提交已确认”仍可恢复，以及同步提交等待中连接取消的处理；产物卷须明确何时可确认封存。替换 PostgreSQL 或存储实现时保留同等事务与持久语义，并重新验证对应故障范围。基础设施监控不能仅以服务进程存活作为复制持久保证。

## 参数与证据关联

- 拓扑、仲裁、隔离设备、卷与 VIP 在 CIB 中配置；服务及卷的 stop 超时与 `on-fail=fence` 保持关联。
- `failure-timeout=180s` 高于范本最长操作超时 120 秒；`cluster-recheck-interval=15s` 支持隔离通道恢复后的原生重试。目标环境调整超时后同步复核该关系。
- 数据库 TLS、角色与连接由[共享部署](../shared/README.md)配置；复制与存储参数使用基础设施产品原生配置。Worker 不获得数据库凭据。
- 任务重放使用已有 `replay_safe`、次数预算和退避参数。重试前核验原尝试真实退出、工具结果结清和当前 E2AG 权限。不同 Attempt 使用不同执行 Grant，保留同一逻辑 Run。

D01-3.01 交付控制面主备、旧主隔离与既有恢复链路的集成。D01-3.02 提供物理跨主机资格环境，D01-3.03 验证复制及完整企业故障/SLO，D01-3.04 负责交付接受；这些资格继续保留原验收要求。
