# 任务完成量与运行观测

任务页提供最近 24 小时和最近 30 天的完成量趋势，分别展示成功、失败和取消，并区分窗口内成功数、历史成功数、当前排队量和实际并发。趋势和任务列表共用执行配置筛选及实时对象权限。

## 持久计数

`runtime_run_outcomes` 以 `(scope, run_id)` 唯一标识一个 Run 的首次终态。任务首次进入 `succeeded`、`failed` 或 `cancelled` 时，终态事件、Run 状态与计数依据在同一事务提交。记录包含事件身份、版本、摘要和原事件时间。

后续输出留存、恢复补报和终态审计不增加完成量。失败尝试进入 `retry_wait` 时尚未成为失败任务；最终成功仍只记录一次成功。父子任务分别有独立 Run，各计一次。业务上层的工作单、代码覆盖率和共享代码去重保持各自口径。

小时/日查询使用固定 UTC 桶，末桶截止观测时刻。查询返回窗口总量与当前可见范围的全历史总量。权限或执行配置筛选改变时，可见历史总量随之改变。导入历史仍通过原历史查询访问，不并入这组原生任务计数。

[Prometheus 计量指南](https://prometheus.io/docs/practices/instrumentation/)区分可累加事件和当前状态；[OpenTelemetry 数据模型](https://opentelemetry.io/docs/specs/otel/metrics/data-model/)区分累计量、区间量和时间窗口。DiOS 以持久事件身份维护计数依据，窗口统计与运行状态快照分开返回。当前接口不是 OTLP/Prometheus 导出器。

## 升级与历史

独立 `outcome_version=1` 迁移从历史事件中按 Run 选取最早终态版本，保留其时间和摘要。迁移与新 schema 版本提交在同一事务完成，重复迁移不重写结果。备份及恢复包含新表。

升级前排空并停止旧版本写入者，再迁移和启动新版控制面/Worker。历史终态缺少事件依据时，接口返回 `coverage.complete=false` 与缺失数量，界面明确统计不完整；不以当前时间补造历史。

计数按权限和范围实时聚合，使用 scope/完成时间索引筛选窗口。按人变化的共享权限不缓存为全局总数。长期、大规模历史的查询成本仍需容量实测。

## 活跃任务观测

活跃观测关联当前 Attempt、Worker 实例、心跳、租约、进程身份和模型 Session。确认运行中的会话须同时具备新鲜 Worker 心跳、有效租约、新鲜进程观测及有效进程/会话身份。暂停进程不计入运行会话；证据不完整时实际并发返回未知。

接口返回排队、等待重试、恢复对账、观测过期、进程退出/暂停、尚未确认执行，以及准备、创建会话、等待模型、输出和校验阶段。新鲜执行超过 15 分钟没有有效输出时给出静默提示。提示不取消、重启或重复派发任务。

未结束任务的诊断最多返回最早的 200 项，并标记截断；状态数量仍覆盖完整可见范围。截断时实际并发保持未知，已确认会话数是已返回样本中的确认数量。

页面请求有 10 秒超时，正常每 5 秒刷新。请求失败保留同一筛选范围的上一份数据并标记看板更新失败，同时将并发展示切为待确认。切换筛选时清空旧范围数据。调度器自身心跳与进一步故障归因继续在 #46 建设。

## API、CLI 与验证

`GET /api/os/runtime/overview` 接受 `period=hour|day`、`buckets` 与可选 `profile_id`。小时最多 168 桶，日最多 90 桶。`GET /runs` 同步支持 `profile_id`。API 沿用身份及逐任务读取权限，操作员与应用身份各自只看到原任务列表允许的范围。

本地可信管理 CLI：

```sh
dios runtime overview --period hour --buckets 24
dios runtime overview --period day --buckets 30 --profile-id review
```

CLI 查询所选 scope 的 Console 任务，包含本地管理员可访问的应用任务；HTTP 查询额外应用当前登录身份的权限过滤。计数、窗口和观测算法一致。

[验证记录](evidence/runtime-overview-20261125.json)包括 SQLite/PostgreSQL、UTC 边界、首终态去重、事务失败回滚、历史回填、重启与备份、对象共享/撤回、执行配置筛选，以及实际 HTTP API 驱动的中英文桌面/手机页面和看板断连。
