# 父子任务的整组容量预留

DiOS 在父任务创建 Attempt 的同一事务内，为固定 Profile 声明的有界子任务树预留执行位置。子任务使用所属树的预留，父进程等待时保留实际占位。多个父任务竞争同一容量时，完整树放不下的父任务继续排队。

## 方案依据

[Ray Placement Groups](https://docs.ray.io/en/latest/ray-core/scheduling/placement-group.html)提供原子资源组预留和子任务调度约束。[Ray 嵌套任务](https://docs.ray.io/en/latest/ray-core/tasks/nested-tasks.html)还允许阻塞任务释放逻辑 CPU；DiOS 的并发账本统计实际执行尝试，因此采用整组预留，继续按真实进程记录等待父任务的占位。

本实现沿用既有 scope 事务串行化、Attempt 和持久事件，不引入新的调度服务或存储表。CPU、内存及宿主隔离继续由运行适配器和 Infrastructure 承担。

## 预留与计账

- 根 Profile 的 `max_children` 是整棵树的子任务总数上限，包含各层后代。父任务为自身加上该上限申请位置。
- 根据固定子 Profile 的摘要遍历至既定深度，预留可能适用的 Profile 配额；主体配额沿用 E2AG 工作主体。多个 Profile 约束采用保守上界，容量不足时根任务排队。
- 预留写入原 `attempt.claimed` 事件，与 Attempt 创建原子提交。控制面重启后从持久事件读取；远程网关独立计算，忽略 Worker 提供的预留声明。
- 实际子任务占位消耗所属树已预留的位置，同一额度不重复计数。子任务仍受当前全局上限、父级预算、期限及 E2AG 授权约束；切换到未固定的子 Profile 被拒绝。
- 父任务取消请求或执行结果未知时，预留保持。确认终态后释放尚未使用的位置；仍存活或未知的子任务继续按实际 Attempt 占位。

Console/API/CLI 将实际占位、子任务预留和可用位置分别呈现。`tree_reserved_slots` 表示尚未被实际执行占用的树内位置；实际并发仍来自进程和会话观测。排队详情考虑整组所需位置，避免显示“还有一个空位”却无法启动需要多个位置的父任务。

## 运行条件

管理员应按实际执行资源设置配额，并为声明的子 Profile 配置可运行的 Worker。容量预留不创建宿主或 Worker。整组上界放不下时，任务保持排队；可按实际业务并行需求配置较小的 `max_children`，上限不会自动放宽。

活动任务的旧版本事件没有树预留，保留既有阻塞诊断；新版本通过排空升级投入使用。运行中下调配额可以暂停后续领取，现有进程和未知结果继续计账。任务取消、额度调整及 Profile 变更均不能扩大 E2AG 权限。

## 验证状态

SQLite 与 PostgreSQL 的独立连接竞争、三层子任务、跨 Profile 预留、取消/未知保留和确认终态释放已通过。真实 Docker 父子容器在总额度 2 下完成两组任务，观测到的实际并发最高为 2，最终占位和预留归零。
