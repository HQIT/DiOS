# 身份服务故障时的执行暂停与续接

所属：#30 / K01-2；衔接 #33 的来源身份及 #34/#35 的 E2AG 授权与撤销。

## 成熟方案与接入选择

[Docker pause](https://docs.docker.com/reference/cli/docker/container/pause/) 通过原生 freezer 暂停容器中的进程，可保留当前进程、内存和连接状态。Windows 仅 Hyper-V 容器支持该操作。DiOS 的 Docker RuntimeAdapter 接入原生 pause/unpause，并绑定原容器启动实例；其他执行器通过可选 `SuspendableRuntimeAdapter` 能力接入。

[Temporal Activity](https://docs.temporal.io/activity-definition) 用持久工作流、检查点与幂等活动控制重试。重新执行活动仍可能重复副作用，外部模型会话和工具调用需要明确的幂等、查询或续接契约。当前短暂身份服务故障优先保留原进程；执行器重启、主机迁移与跨服务副作用恢复继续按各自能力资格推进。

| 执行能力 | 处置 |
| --- | --- |
| 原生 Docker 暂停/恢复 | 暂停原实例，重新核验授权后继续；本地真实 IdP + Worker 已验证。 |
| 远程 Docker Worker | 复用同一 Adapter 和授权门槛；mTLS 工具入口允许在动作前等待身份复核，双物理主机故障资格待验证。 |
| 无暂停能力的执行器 | 停止并保留输出、退出证据；按已授权的恢复策略处置。 |
| 执行器/主机重启后仍有暂停容器 | 保留原对象和待对账状态，不由新 Worker 自动解冻或重新派发；受控接管为后续验收。 |
| 外部托管 Agent 或厂商模型连接 | 按协议的取消、查询、会话续接能力资格处理；本地进程冻结不会暂停远端模型的时钟。 |

## 授权与执行语义

仅 `AUTH_PROVIDER_UNAVAILABLE` 进入有界复核。撤权、身份失效、授权期限、策略变化、所有权过期和其他永久错误保持拒绝。初始执行前最多等待 15 秒；进程启动后最多等待 60 秒，且受原 Worker 总执行期限约束。退避为 1、2、4、5 秒，随后保持 5 秒；Provider 网络请求继续使用原超时。

身份暂不可用时，Worker 读取原进程实例并调用原生 pause，确认状态为 `paused` 后记录观测。等待期间持续核对当前 Work/Grant 和原 lease epoch，更新心跳与进程观测。恢复前重新执行 E2AG 检查，再次确认所有权，并对同一 `process_instance` 执行 unpause。原 Run、Attempt、Session、工具调用和审批关联保持；正常 Grant 续期仍受原 Work 绝对期限约束。

工具通道只在动作前的主体/所有权检查处等待。原请求进入后续动作一次，保持调用 ID、参数摘要和审批版本；等待本身不会重新调用模型或执行工具。连接丢失、未知响应和未知副作用继续采用原对账语义。远程工具网关在同一动作前置检查应用该等待，保留原 mTLS 身份复核。

暂停期间的撤权、到期、取消或等待超限触发受控终止并保存现场。冻结容器采用本机 cgroup v2 的 `cgroup.kill` 整组终止；执行节点须具备相应权限。能力缺失时保留冻结对象并进入待对账状态，不提交终态。Docker kill 的自动解冻存在子进程执行窗口，详见[终止机制与原生证据](managed-lifecycle-10.md#冻结后的终止与-e2ag)。取消的终态需再次读取取消请求并确认实际退出，避免等待期间到达的取消被归成普通失败。

暂停与恢复仍是执行器动作，数据库授权提交与外部执行器之间的严格撤销排序继续由 #35 验收。在途远端工具动作需要自己的完成或取消证据。

## API、CLI 与 Console

Run 详情中的 Attempt 新增 `runtime_state`；`confirmed_running` 不包含暂停进程。Worker 状态 API/CLI 新增 `confirmed_paused_processes`，暂停进程和其会话不计入运行并发，仍占原 Worker 槽位。观测过期时保留未知状态。

Console 分别显示暂停阶段、进程观测与 E2AG 复核提示，沿用中英文和主题设置。授权来源的定时观测与实时执行暂停独立；前者的周期不决定 Worker 何时暂停。
