# E2AG 与开放 Agent 接入

日期：2026-11-11 · F01-3 勘察结论；实施由 F02-1、K03、K01-4/K01-5 承接。

## 集成原则

E2AG 是 DiOS 的执行治理能力。接入 Agent 时，平台先计算主体、工作、资源、动作和参数的有效授权，再由实际控制点执行允许、拒绝、审批与撤销，最后关联执行结果。ACP/A2A 提供交互协议，MCP、受控工具代理、沙箱及可信执行钩子提供不同的动作控制入口。

统一链路为：**WorkItem/Run → Attempt/Session 身份绑定 → E2AG 策略与审批 → 执行边界 → 工具结果/未知结果 → 审计与产物**。原始请求、有效授权、策略版本、决定、转发意图和结果分别记录；终端用户身份与平台服务账号分开。

## 各接入路径如何使用 E2AG

| 路径 | 集成方式 | 必须补齐的控制与验收 |
| --- | --- | --- |
| 平台托管 DiAgent | 使用当前任务 grant 和内部 MCP 网关，限定工具/参数/资源 | 将 grant 从任务 ID 扩展到 Run/Attempt/Session/epoch；源码只读、容器/进程和网络策略配套。 |
| Cursor/Codex/Claude ACP | Adapter 将权限请求关联到 E2AG 决策；MCP 地址由平台注入受控代理 | 权限回调只能覆盖 Agent 实际询问的动作；内置 Shell、文件、网络需沙箱/可信钩子或受控工具替代。 |
| dsh ACP / 扩展接口 | 标准 ACP 处理会话，MCP 走网关；可评估 dsh 的工具执行前钩子与后端沙箱 | 固定扩展版本；验证拒绝发生在执行前，记录取消/子任务/后续动作的授权变化。 |
| 远端 A2A | 委派入口授权、数据外发、任务预算与结果接收由平台治理 | 要求远端提供可验证执行钩子、受管工具入口或独立治理服务；不可见能力如实登记，按风险逐步扩展接入。 |

模型会话和 E2AG 网关测试分别有证据，目前尚无 Cursor→E2AG→真实工具的联合验收结果。该链路由 #56 接通、#34 提供控制能力、#58 验收。

## 不足与扩展任务

| 瓶颈/不足 | 提升方案 | 任务与验收 |
| --- | --- | --- |
| 外部权限语义不一致 | 标准化主体、动作、资源、参数、一次/会话授权；保存原始协议请求 | #25/#27/#56：同一策略在不同 Agent 下得到一致决策；不支持映射返回明确原因。 |
| 内置工具绕开 MCP 控制面 | 分离 MCP 与原生工具控制面；采用沙箱、可信钩子或受控工具代理 | #34/#58：对文件写入、Shell、网络和子 Agent 分别做实际拒绝测试；源码摘要及工具侧记录证明结果。 |
| 15 分钟 grant 与长任务 | 续期绑定仍有效的 Run/Attempt/epoch、主体、原授权范围与预算；撤销后续期失败 | #30/#33/#34：跨到期边界继续合法读取，撤销/换所有者后旧 grant 拒绝；续期不能扩大权限。 |
| 任务与尝试/会话绑定不足 | grant 绑定 Attempt、Session、Worker 身份、策略版本和 fencing epoch | #25/#30/#34：重试、会话替换和 Worker 失效后旧授权不可复用。 |
| 兼容模式下未声明治理可继续运行 | 受管工作负载准入要求完整治理配置，历史兼容路径独立标识与迁移 | #34：缺失配置拒绝受管任务；不得仅凭 enforce 配置宣称全部动作已受控。 |
| 结果丢失及副作用未知 | 复用候选实现的持久意图与结果未知语义，增加业务幂等/查询对账 | #30/#32/#34：先落意图再执行；失败保留现场；没有幂等证据不重发。 |
| 复杂参数与委派边界 | 将产品集成参数约束纳入版本化策略；约束路径、资源、工具及子任务授权交集 | #35：参数变更需复核，委派不能扩大范围；异常策略明确拒绝。 |
| 治理开销与长期证据规模 | 度量决策/持久化/转发耗时、拒绝延迟、审计增长、并发一致性与缓存失效 | #26/#46/#54：受控负载下给出 P50/P95/P99 和吞吐；可配置缓存不能延迟撤销生效到超出约定。 |

先完成策略、身份、控制点和证据的最小闭环，再依据实际瓶颈扩展性能与治理表面。每个不足有责任任务和退出条件；供应方协议缺口可以通过 Adapter、受控工具或沙箱补齐，仍须验证实际效果。

## 首轮联合验收样例

固定合成仓库及只读策略，分别通过 Cursor ACP 和 DiAgent/标准 A2A 参考路径请求受控检索。允许的读取返回结果；越权路径、文件写入、执行业务脚本和外发请求被阻止；撤销后新动作与续期均拒绝。记录 Run/Attempt/Session、策略/审批、grant/epoch、工具接收记录、产物摘要和最终状态。

再注入执行后断连、结果提交失败、过期、重启和所有权变化，确认未知结果进入对账，拒绝不会触发执行，成功不会丢失审计。该样例由 #58 承接，厂商能力变化触发兼容复核。

## Worker 工作授权接入点（2026-11-13）

#30 已提供 `authorize_work(context, action)` 组合接口：execute 与 accept_result 分离，绑定 Run/Attempt/Session、Worker、原 lease epoch 和 authorization epoch。声明 work_authorization_ref 时缺少 verifier 会明确拒绝启动或恢复接收；既有可信本地配置保持兼容。恢复事务对版本和撤权重新核验，补报沿用原身份，不续发执行权。

#34 需把现有 E2AG 策略/授权存储接到该接口，并补齐授权兑换、有效期与预算、长任务续期、原生工具控制和撤销传播；#33 提供服务身份与凭据解析。接口及竞态测试见 [Worker 恢复对账](worker-reconciliation-30.md)。
