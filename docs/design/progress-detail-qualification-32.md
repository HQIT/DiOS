# 轻进度与详情同步故障资格

DiOS 用版本化事件记录任务进度，用内容摘要和已确认偏移传输完整产物。进度事件无需携带完整正文；消费者按任务版本拒绝重复和过期更新，详情传输可从持久偏移继续。原 Run、Attempt、Session 和产物关联始终保留。

事件投递采用[事务 Outbox 与幂等消费](https://docs.aws.amazon.com/prescriptive-guidance/latest/cloud-design-patterns/transactional-outbox.html)的既有路径。完整正文以二进制分块传输，合并后校验 SHA-256 并解码；UTF-8 字符跨块时保留原字节，符合[增量解码的状态要求](https://docs.python.org/3/library/codecs.html)。

## 实测结果

[工程证据](evidence/progress-detail-qualification-20261126.json)包含 25 项通过、零跳过的测试。组合场景使用真实回环 mTLS、独立 Worker/控制端产物目录，以及 E2AG 绑定的原任务和会话。

| 场景 | 可核验结果 |
| --- | --- |
| 详情请求暂停 | 3,000,014 字节详情暂停期间，四阶段进度及心跳在 0.466 秒内完成；最新事件 490 字节 |
| 事件重复与乱序 | 先应用最高版本，再倒序重复全部旧事件；投影版本保持最高值 |
| 分块已提交、回执丢失 | 客户端收到连接错误，服务端保留 65,536 字节偏移；未完成详情不可读取 |
| 分块乱序与冲突 | 跳过偏移和同偏移不同内容均被拒绝；相同分块重复提交不增加存储记录 |
| 控制服务对象重建与续传 | 从持久偏移继续；再次上传相同内容复用已完成对象，共 46 个分块 |
| 中文与 emoji 跨块 | 37 个分块不能独立按 UTF-8 解码；完整回读字节、JSON 和 SHA-256 均一致 |
| 关联保留 | 保留原 Run、Attempt 和 Session，完整产物关联原 Attempt |
| Worker 恢复与授权 | 断网结果从原尝试恢复，丢失完成回执不重复产物；旧所有者、撤销授权及失效机器身份被拒绝 |

专项还覆盖本地报告队列的持久回执、退避和有界容量，以及未完成上传的备份与恢复。产物中断清理测试保留既有维护锁文件，检查本次上传未留下部分内容。

## 容量与故障范围

远端当前单产物上限 8 MiB、单 Attempt 总量 32 MiB。更大的业务归档需拆成有界产物；持续评审的驾驶舱展示与业务归档映射由上层应用接入。

本次暂停注入位于详情请求进入控制事务之前，证明详情网络请求与轻进度请求可独立推进。数据库或共享磁盘整体不可用时，进度同样依赖存储恢复。物理跨主机断网与多节点持久性由 W4 验证。

```bash
backend/.venv/bin/python scripts/qualify_progress_detail.py \
  --output workspace/progress-detail-qualification.json
```

需要 Linux 和 OpenSSL。测试创建临时数据库、证书及回环监听，结束时清理；不访问模型服务或生产评审数据。
