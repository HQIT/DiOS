# 工具结果回执与恢复对账（#30/#34）

状态：工程验证已完成，产品验收待用户参与（2026-11-13）；未提交、未推送。证据见 [工程验证记录](runtime-engineering-verification-20261113.md)。

## 结果如何保留和恢复

工具返回后，执行侧先将原始响应和回执写入本地内容寻址存储，再更新调用账本。控制数据库暂时不可用时，完整回执可在恢复后补入原调用；部分响应保留为待对账。重复恢复复用同一回执，恢复过程不调用上游工具。

```mermaid
flowchart LR
  A[E2AG 授权及单次审批] --> B[事务提交派发证据]
  B --> C[固定原身份及工具契约]
  C --> D[执行受控工具]
  D --> E[持久响应与回执]
  E --> F[校验原身份、摘要及派发证据]
  F --> G[原调用账本与产物关联]
  E --> H[Worker 周期恢复或管理入口]
  H --> F
  G --> I[任务成果另行授权接收]
```

本地意图先于实际工具调用写入。结果与回执采用临时文件、fsync、原子独占链接提交，内容以 SHA-256 标识；相同内容可复用，已存在的回执不能被另一份结果覆盖。回执包括原调用、Run/Attempt/Session、Worker/instance、租约及授权代次、工作策略/权限/参数摘要、审批消费状态、工具注册契约和派发版本。凭据仅保留引用，令牌不进入回执。

回执 JSON 上限 256 KiB，原始结果上限 1 MiB。完整 JSON 按 UTF-8 解码，二进制产物按字节存储；读取先验证摘要与长度。冻结的工具结果 Schema 与数据库登记摘要相符后才用于校验，因此当前工具目录变更不改写历史结果的判定契约。

## E2AG 的责任

派发继续检查当前授权、会话、所有权、审批及策略。回执恢复验证历史派发证据、原身份和完整权限元组，保留已经发生的调用事实。授权撤销、过期或旧 Attempt 结束后仍可登记历史事实；恢复不续期 Grant、不派发新动作、不直接改变 Run 为成功。

任务成果接收继续经过 `accept_result` 和 Run 所有权/授权校验。恢复副本处于 `restore_hold` 时，回执写入同样暂停。更新调用状态、产物关联及恢复审计在一个事务内提交；审计失败时数据库更新回滚，本地回执继续保留。

| 回执条件 | 调用状态与处理 |
| --- | --- |
| 完整、身份/摘要/契约有效，工具正常返回 | succeeded，记录工具结果 |
| 完整且工具声明 isError | failed，保留错误响应 |
| 部分响应或结果不符合契约 | result_unknown，保留现场 |
| 缺少回执、摘要损坏、身份或派发证据不符 | 拒绝恢复，原账本与文件保留 |
| 同一回执重复提交 | 返回原结果，不重复链接产物或增加调用版本 |

外部工具已经执行、但完整回执尚未持久化时发生进程崩溃，仍可能留下未知结果。此类情况需要工具侧查询、业务幂等证据或后续独立对账器。当前恢复入口不接收人工指定的成功状态。

## Worker、管理入口与升级

Worker 周期维护先补报已有报告，再按 profile 有界扫描未决工具调用，随后执行原 Run 恢复逻辑。每轮至多 100 条，游标循环前进；有本地回执时校验恢复，缺少回执且观测超期时登记待对账。局部回执错误保留调用并记录本轮原因，数据库失联交由 Worker 现有退避处理。

Console 工具详情显示本地回执可用状态，并提供“校验并恢复回执”。API 使用操作员认证及原调用版本：

```text
POST /api/os/runtime/runs/{run_id}/tools/{invocation_id}/receipt-recover
{"expected_version": 3}

dios task tool-recover RUN_ID INVOCATION_ID --revision 3
```

`receipt_available` 表示当前服务能读取回执文件入口，校验结果以恢复操作返回为准。它不表示远端 Worker 在线或回执已经有效。

排空状态新增 `tool_calls_inflight`、`tool_results_unknown`。存在已派发或结果未知的工具调用时，即使 Worker 已结束也不满足切换条件；运行中的工具和任务继续自然结束。结果未知继续阻止 Run 提前成功和再次入队。

## 备份及 Provider

SQLite 备份将快照中已派发调用对应的本地回执，以及尚未关联到数据库的响应/回执对象纳入备份包。含回执的备份使用 format 2，校验文件名、原调用关联、对象集合、长度和摘要；无回执包继续使用 format 1。恢复支持两种格式，重建回执后保持全局调度关闭。旧版恢复器不支持 format 2，回滚需保留相应恢复工具。

当前为受信主机上的本地 Provider，Worker 与管理服务需使用相同产物根目录才能共享回执。跨主机发送方认证、远端回执传送及对象存储 Provider 由 #33/#34 承接；跨主机回执须验证发送者、原执行绑定、内容摘要和防重放，不能直接接受远端上传的自述成功。企业多节点仍为既定目标。
