# ADR 0010：SQLite 作为轻量 Runtime 阶段性默认

日期：2026-11-11 · 状态：接受。承接 ADR 0009 与用户确认的“继续推进，后续优化”。

轻量控制服务以 SQLite 作为当前默认实现。依据是已有 Runtime 与查询工具复用、原子提交/恢复证据，以及有界 FIFO 写入后的基本混合查询验收。LMDB 保留为可替换候选，后续优化由真实瓶颈触发。

SQLite 的写入口限定在一个控制服务拥有的 Database 实例内：一个执行者、最多 64 个等待者、默认排队时限 5 秒。只读查询使用一致性快照，提交确认后才返回持久受理。关停停止新写入并排空已有请求。跨进程公平性和跨主机共享状态由独立部署设计承担。

当前 Runtime 沿用标准库 SQLite 驱动与已有 journal 配置，显式 synchronous=FULL。WAL 启用须采用包含 WAL-reset 修复的引擎版本及对应验收；此前 APSW/WAL 实验不等同于当前驱动配置。

Worker 跨主机通过控制服务 API 接入，禁止把 SQLite 文件作为共享网络数据库使用。控制服务多副本、仲裁、旧主隔离、同步复制和故障切换按照实际部署模型验收；共享状态 Provider 保留 PostgreSQL 路线及替换接口。本次默认选择限定轻量部署。

#32 后续推进历史关联/API 投影、有界离线 spool、备份恢复和升级排空。#30 推进持久调度/恢复及真实 Worker 接入，#34 接入完整 E2AG/PEP。现有业务迁移保持独立验收和排空切换步骤。
