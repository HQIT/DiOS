# ADR 0007：工作授权、E2AG 执行绑定与撤销

日期：2026-11-11 · 状态：接受（设计基线）· 对应 #27。

## 背景

长时间运行、外部 Harness、跨主机执行及静态评审需要持续有效的受限身份。现有任务级 Grant、工具观测和可选治理配置不足以覆盖原生工具及所有权变化。

## 决策

采用三段生命周期：一次 AdmissionReceipt、持续 WorkloadAuthorization、短期 ExecutionGrant。权限按调用者、服务、工作和资源取完整元组交集；执行绑定包括 Run、Attempt、Session、Worker 与租约 epoch。API、CLI、Console 和工具路径共享权限矩阵。

E2AG 决策、实际 PEP 与证据分工明确。审批绑定具体动作及参数、单次消费，动作派发前持久化意图。撤销与派发通过同一授权记录串行确定顺序。托管模式授权服务或审计不可用时暂停新动作，远端未受控能力按证据限制准入。

初始 Profile 使用 900 秒准入与执行 Grant、300 秒续期、600 秒审批和默认 24 小时工作授权；租约 60 秒，20 秒续租，撤销 P99 目标 5 秒。容量与安全验证后按版本调整，消费者使用固定 Profile。

## 影响与替代

持续任务可在原始授权期限和预算内自动续期。实现需要可信主体解析、机器身份、数据库原子操作、沙箱与故障验收。纯提示词限制、只在 Gateway 授权和长期宽权限令牌均无法满足严格评审准入；第三方工具不可控时使用可控 Adapter 或受限远端业务路径。

本决议承接 ADR 0005 的 E2AG 持续提升要求。性能优化保留授权交集、当前代次、持久意图和单次审批约束。详细接口、状态、验收及实现责任见 [授权契约](../design/authorization-contract-v1.md)。
