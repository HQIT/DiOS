# ADR 0005：E2AG 接入与持续演进

状态：已接受（G0） · 日期：2026-11-11 · 关联：AP-04/05/09/13、AR-03/04/13、#55/#57。

## 背景

DiOS 需要治理不同来源的 Agent。#57 证实了 E2AG 的 MCP 网关及候选参数、stdio、调用意图能力，同时记录了原生工具、长任务续期、授权身份绑定与性能证据缺口。企业工作要求这些能力随实际接入持续提升。

## 决策

1. E2AG 是 L1 执行治理的组成部分，统一策略决策、执行控制点和证据契约。L2 保有组织授权和审批人选择；L3 保有领域规则。
2. 接入路径显式声明实际控制点：MCP 网关、Runtime 沙箱、可信工具钩子或可验证远端治理。接入协议、模型品牌和操作系统不构成授权保证。
3. 受管工作负载按能力准入；所需控制点缺失时拒绝分派，或经策略允许选择已验证 Adapter。原生 Shell/文件/网络控制列入 #34，远端可验证治理按端点扩展。
4. 授权与 Run/Attempt/Session、资源、参数、策略版本和所有权 epoch 绑定；委派取权限交集，长任务按当前权限续期，撤销作用于后续动作。
5. 执行前持久保存意图；结果未知先对账。必要决策/审计不可用时停止相关动作；明确的低风险降级策略记录范围、期限与补记责任。
6. E2AG 瓶颈必须形成可复现负载、改进任务和回归证据。按 #26 定义的目标测量 PDP、PEP、审计、转发及撤销传播，#46 观测，#54 容量验收。缓存、并行或异步优化须保持权限版本、撤销和持久确认语义。

## 方案取舍

集中契约便于跨 Agent 复用规则；实际控制点随 Runtime 分布，增加能力协商和故障处理工作。网关先承接可控制的 MCP 路径，沙箱与可信钩子补充原生工具，远端路径提供等效证据后接入。插件和控制点可替换，版本及准入证据保持可追溯。

## 交付与复审

#25 固定对象与接口，#27 固定授权矩阵；#33/#34/#35 实现身份、基础与高级治理；#56 完成协议映射；#58 进行跨 Agent 联合验收。证据继承 #57，下一阶段验收覆盖真实拒绝、审批、撤销、续期、过期 epoch、结果未知和运行中排空。

决议与固定版本见 [G0 评审记录](../architecture/review-v0.3.md)。新增控制点、远端信任模型变化、性能优化影响授权语义或授权绕过时复审。
