# ADR 0008：E2AG 治理语义与实现机制分离

日期：2026-11-11 · 状态：接受架构方向；生产后端选型待基准评审。

依据：用户明确提出 E2AG 是治理策略，应比较更合适的实现，数据库需按并发及性能评估。该决议替代 ADR 0006 中“PostgreSQL 已选为首个多节点权威后端”的选型结论；领域对象、幂等、fencing、未知结果和证据约束继续适用。

## 决策

E2AG 定义来源、任务、能力、动作及证据之间的治理语义。策略引擎、授权状态服务、PEP、事务库、协调服务和证据日志分别通过能力契约接入。生产实现由正确性、性能、恢复、成本、许可与运维评审确定。

跨对象原子性采用语义接口表达：单次认领、条件转换、审批消费与意图创建、撤销与派发排序。SQL 事务、事务 KV 或有复制保障的分区状态机均可实现；通用 Provider 接口不暴露 SQLAlchemy Session、PG advisory lock 或特定 SQL 类型。独立数据库、协调器与消息日志之间的原子提交需专门证明。

纯策略判定可本地执行；关键授权状态转换与调用意图需要在既定持久化及一致性等级下确认。查询投影、详情归档和趋势分析可异步更新。受控动作仍受 #27 的严格撤销 Profile 约束；本地缓存与短期能力不能隐含放宽撤销语义。

本轮 SQLite/PostgreSQL 代码是正确性参考后端，Workspace 级串行锁列为性能对照。优化版本以 Run、Approval、Grant 和队列分区等冲突域组织并发，允许无关任务并行。E2AG 实现评测优先比较数据布局与同步提交路径，再比较后端。
