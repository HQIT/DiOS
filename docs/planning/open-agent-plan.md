# 开放智能体接入：计划调整与下一批工作

日期：2026-11-11 · 适用基线：ARCH-BASELINE-0.2 · 任务状态以 [GitHub Project](https://github.com/orgs/HQIT/projects/2) 为准。

## 建设主线

DiOS 作为治理底座接入自研和第三方 Agent，loop/harness 由具体实现提供。整体路线保持 P0—P4；开放接入进入领域、权限、恢复、产品服务和交付的共同验收。

首批范围为一条 A2A 任务路径和一条 ACP（Agent Client Protocol）交互路径，至少使用两个不同来源的 Agent，包含第三方 Harness。具体组合由能力勘察确定；DiAgent、dsh、Cursor、Codex、Claude Code 均纳入候选矩阵，后续按兼容能力扩展。

## 受影响的工作包

| 工作包 | 调整后的交付重点 | 验收变化 |
| --- | --- | --- |
| F01 架构与领域/容量 | 新增能力勘察；区分 Agent 身份、实现/端点、协议和生命周期 Adapter；Run/Task/Session 映射；托管与远端负载 | 先取得接口证据再固定契约，记录未知版本、缺失能力与外部依赖假设 |
| F02 授权 | 平台身份、外部账号和端点凭据分开；审批、撤销及数据外发按实际边界定义 | 入口授权与内部动作约束分别验证，取消请求与远端确认分别记录 |
| F03 产品与验收 | 展示 Agent 绑定、能力、交互状态与限制；增加跨协议、跨实现用例 | 未支持操作、未知结果和缺失用量可识别 |
| K01 运行与接入 | 生命周期、持久调度、协议适配分别实现；新增跨智能体联合验收 | 断连重连、重复事件、产物、审批、取消与恢复贯通 |
| K02 版本与数据 | 保存 Adapter/端点版本、能力快照和远端引用，区分可控构建与不透明实现 | 配置回退、远端版本回退和外部数据恢复各有支持边界 |
| K03 治理 | 基础授权先以可控 Adapter 验证，真实第三方组合进入联合验收 | 高风险任务按控制点准入，远端通知与强制执行证据分开 |
| S01/S02 员工与工作 | 员工按能力绑定不同 Agent；上下文转交、远端会话、知识外发与成果回收受控 | 切换实现保留身份和业务历史，保持 ACL 与人工接管 |
| S03 Studio 与运营 | 多 Harness 开发、兼容评测和发布；质量成本按实现归因 | 区分实测、供应方报告、估算和未知；远端不可控升级有处置 |
| K04 Registry 与观测 | 登记协议、端点、版本、来源、许可与治理能力；关联远端任务和证据 | P1 提供最小能力登记，P3 完善企业准入与运营；未知用量不记为零 |
| A01 行业包 | 声明所需能力与治理要求，通过配置选择兼容执行实现 | 同一业务包验证跨实现运行，能力不足时明确拒绝或要求变更 |
| D01 企业交付 | 托管与远端混合拓扑、会话归属、回调、限流、网络中断、依赖升级 | 平台 SLO 与外部服务假设分别验收，副作用按幂等能力恢复与对账 |

## 依赖与阶段门槛

F01-3 能力勘察可与 F01-0 架构评审并行，为基线收口和详细设计提供证据。F01-1 在 G0 与能力勘察完成后固定领域/API 契约；F01-2 在 G0 后推进容量设计；F02-1 承接领域设计形成可实现的授权契约。

K01-2 持久调度依赖领域与容量契约；K01-1 Local Docker Adapter 是托管实现。K01-4 协议适配依赖统一契约、持久运行和凭据服务，可按远端路径独立推进。K03-2 基础治理使用可控 Adapter 验证。K01-5 汇合生命周期、协议和治理，作为第三方运行进入员工服务与交付的前置验收。

P1 退出门槛包含两个来源 Agent 的受控执行与恢复证据；P2 验证员工/工作身份跨实现连续；P3 验证多 Harness 开发、兼容升级与治理运营；P4 验证混合拓扑和外部依赖故障。

## 计划管理

当前为 12 个工作包、39 个可验收任务。持续评审要求进入 14 个既有任务的范围和验收；新增 A01-5（P2）持续评审参考应用与覆盖账本、D01-5（P4）历史接入/分区切换/回滚。A01 工作包跨 P2—P4，业务参考实现先验证通用服务，完整行业包 SDK 在 P4 完善。多节点与高可用保持企业目标，多租户后置。

P1 必须具备源码只读、持久所有权、分类恢复、排空、事件/产物分离和最小阶段观测；P3 深化企业运营。A01-5 依赖参考验收、跨 Agent 闭环、数据边界与 WorkItem；D01-5 依赖参考应用、安装基线、生产状态存储与备份恢复。历史清点和切换设计可提前准备，生产迁移须满足依赖和独立切换授权。

任务链接：[A01-5 持续评审参考应用 #59](https://github.com/HQIT/DiOS/issues/59)、[D01-5 历史接入与切换 #60](https://github.com/HQIT/DiOS/issues/60)。#57 的 [A2A 有界兼容检查](../design/a2a-contract-survey.md) 记录 8 项差异，由 #25/#56 承接；E2AG 的不足继续扩展，原生工具控制、长任务续期、授权绑定和性能目标进入 #26/#27/#33/#34/#35/#46 等任务。
