# E2AG v1.1 主张—证据矩阵与评审门禁

## 主张—证据矩阵

| 研究主张 | 机制依据 | 隔离证据 | 当前允许结论 | 禁止外推 |
|---|---|---|---|---|
| “跨层”具有独立形式语义 | 授权层集合 $\mathcal H=\{H_E,H_T,H_C\}$、对象映射 $\lambda$ 与 $H_E\rightarrow H_T\rightarrow H_C$ 状态迁移 | RQ1 隔离事件声明/任务创建；RQ2 隔离任务创建/工具调用 | 当前模型明确区分授权层与治理/执行/证据架构平面 | 把任意三段流程均称为跨层治理 |
| 治理目标不能由全拒绝满足 | $GovOK=Sound\land Preserve\land Accountable$ | RQ1/RQ2 同时报告正常路径可用性与违规路径可达性；RQ3 检查证据 | 当前工作负载上同时检查安全、正常可用性和可问责性 | 未测试工作负载上的零误拒绝保证 |
| 来源契约与目标策略治理不同授权对象 | source–type 契约与目标作用域策略分离 | 60例冻结矩阵的 Contract×Policy 2×2 消融 | 两个机制对当前威胁矩阵具有互补覆盖 | 真实流量中的攻击检出率 |
| 单一执行点不足以阻止跨阶段副作用 | 调度前 PEP 与调用时 PEP 观察不同上下文 | 480条配对端到端路径；90条既有模型决策回放 | 两个执行点对当前两类跨阶段违规均不可替代 | 阻止任意提示词注入 |
| 完整中介可保证禁止工具调用不抵达上游 | 任务能力绑定与调用前强制验证 | 上游 HTTP MCP canary 的可达性观测 | 在本文实现路径与假设下，违反能力绑定的调用不可达上游 | 所有传输、所有AIOS及参数级数据流安全 |
| 分阶段证据可定位首个治理失败阶段 | 对象依赖与 stage/outcome 证据链 | 5类故障、100条持久化 trace | 对本文显式治理阶段的首错定位有效 | 一般程序根因分析 |
| 原子状态转移维持 replay 与审批不变量 | 唯一去重声明与条件状态更新 | SQLite 8/32并发、修复前后对照 | 当前 SQLite 路径满足单日志、单终态 | PostgreSQL/MySQL 等后端的同等结论 |
| 自有设施上的 grant–PEP 治理一致性 | 真实 GitHub payload、任务作用域 ToolGrant、Streamable HTTP PEP | qame–demogo 配对回归；允许调用抵达上游；集合外调用403；审计 `upstream_status=null`；canary 状态不变 | 当前部署路径可运行，且集合外工具请求在运行时 PEP 本地失败 | 自然工作负载统计、模型安全率、自然流量违规概率、外部方法优劣 |
| 工具边界输入不能替代跨层上下文 | 官方 OPA v1.17.0 与通用 default-deny Rego 策略 | 49例可调用冻结切片：NoGuard、OPA-Tool、E2AG 总体对齐分别为30/49、34/49、49/49；OPA-Tool 分层为工具策略4/15非允许、审批0/4非允许；8例接口补充验证允许集语义；记录选择规则、排除编号及二进制、策略、输入和投影哈希 | 通用 PDP 可执行任务工具集合规则；跨层对象构造、上下文传播和双 PEP 才覆盖工具边界不可见的约束 | OPA 引擎弱于 E2AG，或 OPA 已具备事件来源绑定、能力生命周期和跨层证据能力 |

## 合作者评审门禁

| 评审意见 | v1.1 通过条件 | 本轮状态 |
|---|---|---|
| 摘要数字过多 | 仅保留一个中心对比结果，其余数字移入实验 | 已处理 |
| 引言短且偏泛化 | 按执行对象、失效机制、设计要求、中心洞见、证据贡献展开 | 已处理 |
| 公式简单且无意义 | 形式化状态迁移、完整中介安全性质与证明概要；每项性质映射算法和实验 | 已处理 |
| 问题定义不概括 | 以主体、对象、信任边界、失败类、目标和范围构造问题胶囊 | 已处理 |
| 框架图是流水线 | 新增三平面静态架构图；原流程图只承担时序解释 | 已处理 |
| 实验要上量 | 明确区分独立规模与重复次数，纳入60例四人盲审冻结矩阵、49例 OPA 可调用切片、700例压力集和一条真实 Connector→Agent→Tool 部署链；跨模型、多连接器和数据库扩量仍待执行 | 最低证据已补齐，外部性仍是主要限制 |
| 负向回归不得依赖模型参与 | 集合外工具名和参数由固定驱动器构造；后续只允许确定性 harness 调用 PEP | 已处理；冻结既有拒绝轨迹，未新增模型调用 |
| 章节编排不像《软件学报》 | 引言不编号；正文按背景、模型、架构、机制、实现、实验、讨论、总结展开 | 已处理；LaTeX 为作者源，初投稿提交匿名 PDF；录用后再按要求提供 Word 排版稿 |
| 未形式化层次与能力，算法记号先用后定义，治理目标不明确 | 定义授权层与对象映射、任务作用域能力的 `Issued`/`ValidGrant`、`GovOK`；算法前定义输入、返回值、辅助过程和局部量 | 已处理；v1.1.24 公式、算法、实现与 RQ 已闭合 |

## 当前剩余阻塞项

1. 已有一组真实 Connector 治理一致性配对轨迹，但多仓库、更多工具类型与数据库后端的独立维度仍不足；
2. 已加入49例可调用冻结切片和8例接口补充上的 OPA 独立引擎基线；AgentSpec、OAP 等 Agent 治理系统因保护对象或公开离线接口不同，仍没有公平的同工作负载原系统数值排名。
