## 合作者评审门禁

| 评审意见 | v1.1 通过条件 | 本轮状态 |
|---|---|---|
| 摘要数字过多 | 仅保留一个中心对比结果，其余数字移入实验 | 已处理 |
| 引言短且偏泛化 | 按执行对象、失效机制、设计要求、中心洞见、证据贡献展开 | 已处理 |
| 公式简单且无意义 | 形式化状态迁移、完整中介安全性质与证明概要；每项性质映射算法和实验 | 已处理 |
| 问题定义不概括 | 以主体、对象、信任边界、失败类、目标和范围构造问题胶囊 | 已处理 |
| 框架图是流水线 | 新增三平面静态架构图；原流程图只承担时序解释 | 已处理 |
| 实验要上量 | 明确区分独立规模与重复次数，纳入700例压力集、三人盲表复核和一条真实 GitHub→DiAgent→MCP 部署链；跨模型/多连接器/数据库扩量仍待执行 | 最低证据已补齐，外部性仍是主要限制 |
| 负向回归不得依赖模型参与 | 集合外工具名和参数由固定驱动器构造；后续只允许确定性 harness 调用 PEP | 已处理；冻结既有拒绝轨迹，未新增模型调用 |
| 章节编排不像《软件学报》 | 引言不编号；正文按背景、模型、架构、机制、实现、实验、讨论、总结展开 | 已处理；初投稿按官方说明保留匿名 LaTeX/PDF，Word 不作为当前阻塞项 |

## 当前剩余阻塞项

1. 已有一组真实 Connector 治理一致性配对轨迹，但多仓库、更多工具类型与数据库后端的独立维度仍不足；
2. 已加入同一冻结工具调用切片上的 OPA 独立引擎基线；AgentSpec、OAP 等 Agent 治理系统因保护对象或公开离线接口不同，仍没有公平的同工作负载原系统数值排名。
