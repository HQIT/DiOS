# 统一事务排队验收与性能预试验进展

2026-10-01。结论：现成的异步单连接池已通过基本事务及故障验收；已运行的issue工作负载没有出现请求失败或审计缺失。18格短预试验实际启动9格，前8格正常结束，第9格触发整机内存停止门槛，PR的9格未运行。因此本轮不能称为完整性能验收，更不构成正式性能结论。SQLite优化不再作为后续研究方向。

## 本轮变更及公平性

按作者意见，将实验运行器的数据库连接池统一设为单连接、无溢出，由现成连接池排队；G0、G1、G2完全相同。排队包括读写事务，等待计入工作流延迟，不包住外部工具HTTP调用。SQLite DELETE/FULL、提交/回滚及未知结果语义、业务输入、治理规则和资源停止阈值不变。本轮未修改后端实现、生产配置、论文正文或远端部署。相对前轮清单登记的9个后端文件哈希一致。

这是一项普通实验基础设施调整，不是能力治理创新，也不是数据库优化成果。只验证单worker、单应用进程；不推广为多进程或分布式一致性。原失败结果均保留，不用新结果覆盖或改写原问题。

## 基本验收

5项基础设施测试通过：32个事务的更新不丢失、取消排队不占住连接、回滚释放连接、提交后等待外部操作不占住事务连接、池配置有效。既有6项计时测试通过。以上测试在性能计时前结束，本轮没有本任务其他测试与计时重叠。

三个真实本地HTTP故障场景均通过：意图提交失败时上游不执行；读取结果提交失败时只执行一次读取、保留未知结果、不写报告；写入结果提交失败时报告实际写入一次、保留未知结果、不自动重试。这些仅证明所测故障路径，不是恰好一次保证。正常完整流程资格检查1次通过。

故障检查v1因10毫秒启动窗口短于实际调度时间，未发出请求即断言失败；其空结果和`tmp/rr022-perf-pretrial-e6j7fuaq`原始记录保留。v2改成固定一条请求，不依赖启动窗口；正式计时逻辑、时长不变。

## 短预试验结果

沿用两种开发输入×三种配置×并发1/8/32的18格计划，固定随机顺序，每格2秒预热、8秒测量启动窗口，允许已发请求完成。运行165.375秒后停止。实际仅运行issue输入的9格：测量681次、预热224次，共905次工作流，全部成功；独立检查确认报告内容、实际工具操作、任务关联及适用的授权/审计证据相符。9格峰值占用连接为1，结束占用为0；代理工具调用时没有保持该请求的数据库事务。

停止原因是整机可用内存低于15%持续10秒，观测最低14.48%，而非SQLite锁失败或请求错误。采样中驱动、应用、工具进程各自RSS峰值分别约75.4、98.6、35.3MB（各自峰值不能当作同一时刻总量）。退出后的只读快照显示整机可用约5.34GB／15.83%，仍在门槛附近；没有关闭用户程序、重启WSL或修改门槛。该门槛是预设的测量质量及资源保护条件，不表示低于该比例就无法计算。不能据此把资源压力归因于治理方法。
