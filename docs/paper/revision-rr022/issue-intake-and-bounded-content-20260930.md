# rr022阶段报告：非预设报告内容与issue受理开发验证

2026-09-30。本轮回到返修主线，不继续扩展仓库候选。目标是移除旧指纹小试中“报告答案被枚举在授权规则里”的局限，完成真实历史输入上的业务读写开发验证。未启动正式留出实验，未修改已投稿v1.1.39正文/PDF，未部署远端。

## 完成了什么

在版本化参数约束中增加v2有界字符串：报告正文只检查类型和Unicode码点长度（本任务1—2048），对象、版本、来源事件仍精确绑定；不把正确报告或其散列放入授权条件。v1语义保留，字段集合封闭，不做类型强转；有界字符串拒绝代理码点，长度不按UTF-8字节或视觉字素计数，不做Unicode归一化。该扩展仍不是完整JSON Schema、内容语义验证或信息流控制。

原生E2AG、完整上下文OPA替换、共享DiOS准入宿主中的AgentSpec三配置得到相同政策和输入。OPA使用独立Rego，AgentSpec沿用官方规则/ControlledAgentExecutor接入独立自定义谓词，均不调用E2AG参数判定函数。OPA宿主提供原始参数的解析类型及Unicode有效性事实，Rego自行计算长度和对象匹配；这是披露的适配，不是把E2AG判定结果交给OPA。策略签发/持久化与宿主路径仍共享，不能称为三个完全独立系统。

## 输入、业务任务与实际结果

只使用已暴露的VS Code开发issue #337178（归档事件15466644884），没有新增项目或正式样本。输入为先前缓存的6016字节历史issue JSON，独立检查器重新核对归档行及内容散列。

任务是“HTTP读取历史issue → 固定执行器生成受理摘要 → HTTP写入隔离报告”。摘要包含标题是否非空、标题/正文字符数、排序去重标签，以及`awaiting_triage`或`needs_information`队列；不复制标题或正文原文。这比v0.2候选中的“复制标题”更克制，属于开发期输出契约调整，后续正式协议必须同步，不能声称已按原候选冻结。该任务不判断缺陷严重性，也不依赖模型调用。

下表计数均为**每个配置、每个场景**的实际值，三方相同。9场景×3配置共27条运行，但独立业务来源仍只有1个已用开发对象。

独立检查器没有导入报告生成函数或治理谓词，从历史源数据重新计算业务答案，核验27份数据库、24条任务关联、落盘工具记录和报告、审计链哈希，以及三配置输入一致性。它明确把两个诊断内容判错，即“授权通过”没有冒充“业务正确”。主运行原文件保留`passed_execution_pending_independent_quality_check`状态，另存独立检查结果`passed`，不回写原始轨迹。

另外完成19项谓词层边界/反向政策探测（三方判定一致），覆盖最小/最大长度、超长、空串、中文、emoji、组合字符、错误类型、代理码点、字段集合、资源匹配，以及放宽长度上限后同一请求可通过。该组中的AgentSpec仅调用独立谓词，不冒充再次运行官方完整执行器；正式执行器由上述27条运行覆盖。此组只比较预验证的有效政策，不证明任意畸形政策的跨引擎解析等价。

5项无门控HTTP控制均实际落盘或完成读取：错读取对象、错读取版本、错写入对象、超长、错误类型。因此拒绝不是由工具端预先校验掩盖。错读取对象/版本是映射同一真实内容的人工测试别名，不是第二条自然业务记录。全部67项`test_e2ag*.py`后端测试通过，其中新增10项有界字符串测试含签发快照不可被后续Agent配置放宽的集成检查。

## 能说明什么、还不能说明什么

本轮补齐E1公平比较和E4细粒度权限的一个实现前置条件，并让E2业务任务脱离“预置正确答案”的小试设计。三配置结果相同，没有观察到E2AG效果优势。新增长度语义是工程实现，不作为独立创新贡献。

这是确定性开发验证，不是独立留出、生产任务成功率、性能测量或自主Agent执行。固定执行器完成读写，但原生任务终态未推进，数据库中仍为`submitted`；AgentSpec准入由共享DiOS实现，不能计为其独立跨层准入能力。E2AG/OPA入口直接调用本地代理处理函数，下游使用真实loopback HTTP，也不是整个公网HTTP链路。没有访问外部项目写接口、调用模型或远端部署。

实验驱动复用旧准入/任务/HTTP夹具，显式替换任务约束构造、报告生成函数和OPA适配类；AgentSpec子进程转入本轮驱动。没有替换允许/拒绝判定或工具返回值。AgentSpec版本、OPA二进制及既有ANTLR/规则兼容适配沿用先前固定配置；本轮结果保存参与源文件hash和规则文本。
