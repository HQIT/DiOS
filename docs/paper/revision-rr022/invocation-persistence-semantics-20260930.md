# 调用持久化修复：语义与验收边界

本次工程修复源于性能预试验发现的真实缺口：合法读取已在上游执行，但代理随后提交调用审计失败。旧结果和数据库保留，不能把修复后的结果用于改写旧记录。本文件是内部实现契约，不是论文已经验证的性质声明。

## 执行顺序与故障语义

调用仍先通过原有任务能力、工具名和参数约束检查。拒绝分支不生成执行意图，也不访问上游。允许分支在发送 HTTP POST 前，以同一数据库事务保存调用意图行和 `tool_intent` 链条项，记录调用编号、任务/事件/能力关联及请求摘要；不保存凭据或原始工具参数。事件关联缺失或轨迹不一致时，不允许在无法关联证据的情况下继续转发。

意图初始状态为 `outcome_unknown`，其含义是结果尚未获得持久确认，而不是已经执行或一定未执行。意图提交成功后结束该事务，再发送上游请求；不把数据库事务跨越到外部网络操作。意图提交失败则回滚并返回 503，当前请求不转发。

收到上游 HTTP 响应后，代理在另一事务中将意图更新为 `response_received`，保存响应状态码及原始响应摘要，并追加带相同调用编号的 `tool_call` 审计。两者一起提交或回滚。`response_received` 只表示观察到响应，不表示工具业务成功；工具返回错误、HTTP 失败状态和合法授权是不同维度。原有 `allow` 也仅表示授权允许，不是业务完成判断。

结果提交失败时返回 503、调用编号及 `execution_outcome=unknown`，保留已提交意图；读取超时或连接中断返回 502，保留相同的未知状态。请求取消或进程在意图提交后中断，也不据此删除意图。代理不自动重发工具请求。先前合法调用次数仍按原有成功持久化的决策条目计数，因此 `call_count` 不是外部真实执行次数；故障检查必须同时读取意图、结果记录和上游操作凭据。

| 故障点 | 上游可能执行 | 持久证据 | 处理 |
|---|---|---|---|
| 意图尚未提交 | 本次转发没有发生 | 可能没有意图；提交确认丢失时也可能已有意图 | 不转发、返回存储故障 |
| 意图已提交，发送前中断 | 可能没有执行，记录不能据此断言 | 未知结果意图 | 等待人工或外部凭据核对 |
| 上游已执行，响应丢失 | 可能已经执行 | 未知结果意图 | 不自动重发 |
| 上游已返回，结果提交失败 | 可能已经产生业务效果 | 未知结果意图；若提交确认丢失则数据库可能已终结 | 返回不确定状态，按调用编号核对 |
| 结果和审计均提交成功 | 响应已观察并记录 | 意图、响应记录、调用审计相互关联 | 返回上游响应 |

## 并发追加

网关的审计追加由直接覆盖 ORM 缓存列表改为：读取持久链、构造下一项、按原链条件更新，冲突时有界重读。事务失败交由调用路径回滚；不重发 HTTP 请求。这防止该网关追加路径中的陈旧对象覆盖，不能等价为解决所有 SQLite 锁等待，也不能扩展到尚未改造的其他审计写入点。仍需在文件数据库和原性能矩阵中验收。

## 明确不作的保证

外部工具和本地数据库没有分布式原子事务，本修复不是恰好一次执行或自动恢复协议。调用编号用于关联，不是上游幂等键；重复使用 JSON-RPC id 也不能被当作重复业务操作。客户端自行重试仍可能导致外部重复执行，必须由业务幂等键或核对机制解决，不能从本次“代理未自动重发”推导为全系统不重复。

未知状态不会被事后填写为成功。当前未实现自动核对服务、通用工具执行回执、数据库之外的持久锚定；请求和响应的散列值不是加密手段，低熵输入仍存在推断风险。本轮验证限于原有事件关联的 HTTP POST 工具路径和本地 SQLite；GET/SSE、DELETE、其他调用出口、多 worker、其他数据库及所有生命周期写入点不在新增保证范围内。

## 实验与论文边界

故障注入只使用既有开发 issue，并检查零执行、已读取、已写入三种情况。未知结果需同时得到数据库记录、客户端故障响应和上游操作文件支持。后端回归及文件数据库 32 会话追加是辅助证据，不替代真实 HTTP 故障检查和完整预试验。

此次改变了实现和审计步骤，不能继续声称旧的源码冻结完全未变。正式业务比较前须保存继承原冻结的修复清单及哈希，验证业务输入、规则和对照适配未变；独立复核未回收前不运行留出对象。性能必须把新增意图事务的成本计入 G2，不删除该成本来美化性能，也不能把本地短测当作生产性能。
