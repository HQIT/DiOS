# rr022正式比较协议修订：自动核验

2026-10-07，作者在当前会话明确同意以独立实现的自动核验替代新增人工复核的执行门槛，并继续既定比较。本修订在正式方法运行前记录；2026-09-30的协议、采集冻结记录、输入和预期文件保留原样。

实验对象仍为原窗口入选的11个对象：ArcadeDB的4个issue和2个PR、Kibana的5个issue。4个主场景与3个配置形成132条配对运行；每对象3项无门控请求，共33项；每个非空层的首个对象另运行未声明事件、权限合法但报告内容错误两项诊断，3个配置共18条。所有对象均保留，方法、政策、字符预算与工具别名映射不变。

## 验收方式

核验程序直接读取原始快照，按业务规范重算报告。issue核验采用逐字符计数、标签去重与受理条件判断；PR核验采用SQL集合连接重建变更清单，并校验Git树对象哈希。它们不调用被测报告生成函数。预期文件仅供核验程序使用，不传给策略引擎或任务执行器。自动核验实现由研究团队编写，不称作独立人员复核。

检查器在运行前接受已知答案和故意错误报告测试；运行后检查工具服务的实际请求日志、落盘报告、原生任务与授权记录、审计链内容和哈希。正常报告须与独立结果一致；越权场景须在预定执行点终止；内容错误诊断须能够被业务核验器发现，即使其满足授权条件。无门控请求用于确认测试对象和版本别名在工具端确实可执行。

新增人工复核改为可选，不再阻塞方法运行，也不报告该组已获人工复核。原60事件矩阵的四人复核维持原有证据身份。这里评估的是指定实验政策下的授权一致性和业务输出正确性；实验政策由研究团队设置，公共仓库提供历史输入。

## 冻结与执行

正式运行前，先用既有VS Code开发对象检验当前执行路径，随后记录执行源码、规则、外部实现、解析器、依赖版本、输入及本修订的哈希。采集冻结以来两个执行文件的变化是调用意图与结果的持久化处理，记录见invocation-persistence-semantics-20260930.md；不得将新执行快照标作与采集源码完全相同。

方法执行只接收任务输入与政策，不接收正确答案。执行器固定，工具服务监听本机回环地址。保留每次运行及错误，不调整阈值、替换样本或按结果修改规则；基础设施错误单列。正式执行预算沿用6小时。结果按独立对象、主配对、辅助诊断和无门控请求分别统计。

## 稿件表述

正文按实验设定、观测结果及原因解释组织。适用范围集中放在实验设定和讨论，删除反复自我辩护、版本过程和待办式句子。协议变更及复核方式的历史记录放在复现材料和审稿回复中；正文准确说明自动核验及其人员来源，不将其改写成人工盲评。
