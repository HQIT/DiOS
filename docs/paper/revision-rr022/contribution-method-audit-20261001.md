# rr022 贡献与方法闭合审查

2026-10-01。只读核对已投稿 v1.1.39（实际包含 `e2ag-body-v1.1.38.tex`）与当前 `codex/e2ag-research` 工作树。提交基线为 `2bfc5ce`，工作树含返修实现，不能把新实现追认成投稿时已完成的证据。本轮未执行实验、改动正文或生成新论文版本。

## 结论

研究问题可以保留，但目前还不能称方法、实现和证据已经闭合。优先解决三项实质问题：**逐目标算法与事件级实现不一致；能力及调用算法未反映当前实现；授权依赖验证的正文承诺强于已有验证器。** 这些比继续测笔记本吞吐更直接影响论文是否成立。

层次、能力和治理目标并非没有定义：§2.1 已定义事件、任务、调用三个授权层及所属映射，§2.3 已定义能力有效性和 `GovOK`。应修正对应关系，而不是重新堆一套形式化。三个授权层也不能与治理、执行、证据三个架构平面混为一谈。

## 贡献表述建议（尚未写入正文）

候选主张是：针对事件触发任务再调用外部工具的运行路径，E2AG 将来源准入、任务作用域能力和调用时约束组织为可核查的授权状态迁移，并规定各阶段的执行位置与证据义务。

这不是“首次使用能力/PEP/哈希链”，也不是“其他方法不能做到”。其研究价值需要由明确的授权契约、性质与实现映射、消融及公平外部比较共同支撑。若完成核对后仍只能说明常规组件集成，应继续收缩创新表述；不能通过削弱基线或制造输入信息差获得优势。

## 最小后续工作，供作者确认

先确定事件级聚合准入，以及审批至签发期间配置变化的授权边界。这是语义选择，不能仅按哪种更容易跑通决定。建议保留当前事件级准入，单列并解决版本/快照问题，不扩展为逐目标审批系统。

随后集中修订定义、记号、算法、I1—I4 与实现对应表；将已实现的参数约束和持久意图语义纳入，不重跑无关实验。已有结果按代码依赖判断可复用范围，不能默认新旧版本等价。

为保留授权依赖验证主张，建议只补限定模式的离线验证：合法轨迹、缺失授权前驱、对象绑定错误、结果未知。反例应包含“哈希链仍正确但语义错误”的记录，以免实际只测到哈希校验。多目标一致性建议限定为全允许、混合允许/拒绝、待审批及审批恢复四类。以上均是待批准方案，本轮未实现、未运行。

独立工作负载仍沿用已冻结的11对象/132条主配对，等待3对象/12行独立复核，不增加项目或改变规则制造差距。性能和多环境意见仍未关闭，但本轮不恢复长测，也不重新进入数据库优化。
