# 底层连接复用开发对照

2026-09-30。本轮只改变POST代理的HTTP传输生命周期，保留前一轮持久化修复、业务规则、授权检查和原停止阈值。默认配置仍关闭，未部署远端，未使用独立留出对象，未改论文正文。实施前已写[对照协议](transport-reuse-protocol-20260930.md)，旧实现与结果均保留。

## 实现及正确性

每个应用worker可在lifespan中持有一个底层HTTP连接池，但每次调用仍创建独立AsyncClient，不共享Cookie容器、默认认证头或MCP会话状态。当前请求的上游凭据和会话信息逐次传入。每次请求结束仅释放所借连接，不关闭应用级池；lifespan退出关闭池。TLS校验、环境代理禁用、超时、重定向行为及零传输自动重试不变，GET/SSE和DELETE未改造。

81项后端回归通过，其中新增6项验证关闭/缺省路径、池生命周期、安全配置、实际TCP复用、顺序/并发身份隔离、超时不重发以及代理逐次授权。已有三个真实HTTP持久化故障场景也在复用模式下通过：执行前提交失败零执行；读取或写入后结果提交失败保留未知状态，不自动重发。计时器6项断言另行通过，但不计作独立业务证据。

## 预先固定顺序的短配对

固定同一开发issue和完整G2路径，依次执行并发1原模式、并发1复用、并发8复用、并发8原模式；每格新进程与数据库，2秒预热、8秒测量，单轮。后端回归与故障检查均在配对计时前结束。共87次测量，84次完成、3次失败；预热30次，无失败。

工作流延迟仅统计完成请求，失败显式列出，不将失败当策略拒绝。这里的吞吐和尝试数受闭环负载影响，两模式请求数不同，不能直接用失败绝对数宣称可靠性提升。数据只支持本机短轮次中的实现降耗观察，不能作为稳定加速倍数或生产容量结论。

复用的两个单元在全部阶段分别观察到72和101次上游操作，均使用同一个TCP对端端口；原模式分别为18次操作/18个端口、40次操作/40个端口。这与真实socket隔离测试一起支持“连接确实复用”。端口计数不是通用连接计数方法，不能外推长期运行。共享传输的启动初始化另记录约486ms和499ms，未伪装为零成本；本轮同时改变传输初始化频率及连接复用，未拆分两者贡献。上游是本地HTTP，不是TLS握手性能实验。

并发8复用模式发生一条读取后结果提交失败；原模式发生一条意图提交失败及一条报告写入后的结果提交失败。后两种“已执行、结果未落盘”各有未知状态意图和返回的关联编号，无工具自动重发；报告写入失败案例只观察到一次报告落盘。它们没有完整终结调用审计，不能称为完全成功，但也没有出现无持久意图的上游执行。原始故障保留，未事后改写状态。当前结构化错误不能逐条证明底层异常一定是SQLite锁，后续定位须补充不含敏感参数的存储异常分类。

结果中的 `pretrial_checked` 以及配对文件的 `all_cells_passed` 只表示现有脚本的证据核验/停止规则检查，没有表示零失败。正式验收应使用明确的错误计数及完成状态，不沿用容易误解的字段名称。

## 原矩阵复验

保持两输入、G0/G1/G2及并发1/8/32原矩阵，实际运行16/18格，用时约397.5秒。测量786次，其中782次完成、4次失败；预热301次，另有5次失败。最低采样可用内存约26.29%，没有触发内存停止。最后一格为PR、G0、并发32，触发基础设施错误率超过5%持续10秒的原停止条件；PR的G1/G2并发32尚未执行，不能补零或称完整矩阵通过。

9条失败中，6条为准入返回500，对应单元日志记录6条SQLite锁错误；1条为G0准入返回200后连接异常断开，尚未到达上游；2条为G2调用持久化失败，其中一条执行前意图提交失败没有转发，另一条读取已执行但结果提交失败，保留未知意图及调用编号，没有报告写入。此处终结调用审计缺失1项，但没有观察到上游执行缺失持久意图。后两条被结构化捕获，不能仅凭同单元其他锁日志就断言它们的底层异常类别。全部失败记录和归属未知项保留。

本轮issue的G2并发8未出现失败，不推翻前面配对同配置1/38失败；两次短运行的波动不能选择性取最好结果。PR快照为7,278,098字节，issue为6,016字节；PR并发8下G2成功工作流中位数约16.96秒，读取段约14.24秒，G0/G1也存在明显读取耗时。不得把这类含大响应传输、JSON处理与排队的路径耗时当作纯授权判定成本。新增能力检查开销需按已保存的阶段跨度区分。

G0没有E2AG调用门控，也在高并发出现锁错误和连接异常，说明不能把所有高并发失败归因于E2AG判定。另一方面，连接复用后G2仍有持久化失败，说明仅消除重复客户端初始化不足以完成可用性修复。协议停止阈值是保护措施，不是“低于5%失败即可通过正式实验”的验收标准。

过程偏差：矩阵运行期间误执行过一次6项计时器单测（断言耗时0.001秒，命令总时长约1.45秒），不符合本轮“计时期间不并行跑本任务测试”的约定。该矩阵只保留为探索性诊断记录，不纳入正式性能轮次；后续正式验收需要在遵守隔离约定的运行中完成。上述四格配对不受该次重叠影响。

## 证据与主线边界

`transport-reuse-manifest-20260930-v1.json` 记录本轮源码、结果及前驱修复清单的哈希。已验证此前28项冻结中的26项保持不变；前轮的持久化服务、模型、数据库和故障回归也保持不变。新增传输模块、路由接入、配置和lifespan变化单列，不覆盖旧冻结。修改前备份为 `tmp/client-reuse-before-20260930-221036/`。退出后未发现本测量器服务残留；本轮未commit、push或部署。

连接复用是工程实现优化，不构成相对AgentSpec或OPA的治理效果优势。独立11对象/132条配对仍等待复核，不用该预试验替代正式业务比较。下一步限定为无敏感参数的存储异常分型、写事务持有/竞争检查及短回归；先区分锁等待、事件关联和连接异常，再决定修复或如实报告原型运行边界，不继续扩展连接优化或另起数据库选型支线。正式长测和论文数字继续等待验收。
