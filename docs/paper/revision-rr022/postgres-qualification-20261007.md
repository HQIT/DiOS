# PostgreSQL 治理状态与执行证据资格检查

2026-10-07。对应[精简方案 v0.3](heterogeneity-protocol-v0.3-20261007.md)的服务式事务存储替换。修复后17项持久场景及独立证据核验通过，另完成双会话状态检查和审批终态回归；后端全量120项测试、65个子检查通过。这是正式配对前的资格结果，文件入口尚未替换为正式 R4 要求的 HTTP 入口。

## 环境与检查对象

使用隔离的真实 PostgreSQL 16.13、asyncpg 0.30.0，每场景新建数据库。数据库只绑定本机回环接口，采用默认 READ COMMITTED 隔离级别；导出使用 REPEATABLE READ READ ONLY。固定镜像 ID、版本、源码哈希及各场景 SQL 导出随结果保存。没有修改既有数据库或远程部署。

复用文件入口资格组的原生订阅、准入、任务创建、审批、能力签发、调用代理和持久交付路径，仅更换状态数据库。固定执行器替代模型与 DiAgent 容器；客户端通过 ASGI 进入调用代理，代理至工具使用实际 HTTP 连接。工具独立保存接收记录和业务产物，检查器读取独立 SQL 导出、审计链及工具文件，不以运行器的通过标志作为全部证据。

## 结果与缺陷处理

| 记录 | 观察与处理 |
|---|---|
| `postgres-qualification-20261007-v1` | 首个正常场景失败：审计追加需要 JSON 相等比较，PostgreSQL 普通 JSON 列不支持该操作。保留异常和 SQL 导出；仅将审计链列的 PostgreSQL 类型映射为 JSONB，SQLite 仍为 JSON。 |
| `postgres-qualification-20261007-v2` | 17项行为检查通过，但独立检查发现新会话撤销场景的调用意图、响应及拒绝证据被旧会话缓存覆盖。因此本次整组资格不通过，不能只报告调用正确拒绝。 |
| `postgres-qualification-20261007-v3` | 任务完成阶段改为使用已有条件追加审计过程后，17项行为检查、SQL/审计/工具证据核验全部通过；另两会话竞争认领、并发审计追加均满足约束。 |

JSONB 映射依据 PostgreSQL 的[JSON 类型操作说明](https://www.postgresql.org/docs/16/functions-json.html)与 SQLAlchemy 的[类型文档](https://docs.sqlalchemy.org/en/20/core/type_basics.html#sqlalchemy.types.JSON)：本次修复使已有条件更新能够在所测数据库上执行，不改变授权策略，也不代表旧生产表迁移已经验证。

v3 的17项由8个共同治理场景、事件身份冲突、6个进程中止切点、独立会话撤销以及两会话审批竞争组成。共观察到9次预期工具写入，未授权工具或资源、撤销、过期和未批准状态下均无对应工具写入。两份竞争审批只有一份进入有效终态，并只生成一个任务与一份产物；另一个返回 `APPROVAL_ALREADY_DECIDED`。撤销由独立会话提交，新请求会话返回 `TOOL_GRANT_NOT_ACTIVE`，SQL 导出保留对应拒绝记录。

六个中止切点中，五个恢复后完成预期业务；任务创建中途终止的一项仍为未决，未确认交付、未自动重放、没有工具写入。该项通过的是“识别并保留未决状态”，不是业务完成或恰好一次执行。79次工作进程用于阶段隔离，不是79个独立业务样本。

存储原语检查采用两个同步会话：持久认领的条件更新受影响行数分别为0和1；两个审计写入者先读取同一旧链，最终两条记录均保存且哈希关联有效。这些是状态一致性检查，不是并发吞吐量评价。

## 审批终态补充回归

检查终态转换时还发现，过期处理原先根据旧会话中的 pending 对象直接写入 expired，可能覆盖另一会话已经提交的 approved 或 rejected。新增两项测试在修复前均复现该问题。过期分支现与批准/拒绝分支一样，通过 `status = pending` 的条件更新认领终态；认领失败返回 `APPROVAL_ALREADY_DECIDED`，不追加虚假的过期记录。

两项 SQLite 回归及既有三项审批测试通过；另在真实 PostgreSQL 上分别验证“批准后旧会话过期处理”和“拒绝后旧会话过期处理”，独立 SQL 回读确认原终态、首位处理人及审计记录保持不变。该检查使用受控时间推进和原生审批过程，不计为完整任务执行样本。

这项修复发生在 v3 资格组之后：v3 保存其运行时77个源码文件的冻结记录；后续终态检查另存78个源码文件，检查结束时均与冻结指纹一致。不同阶段不混称同一版本的正式结果。后端最新全量回归为120项测试和65个子检查，JUnit 共185条、零失败、零错误、零跳过。

## 对论文的作用与下一步

该组补充“更换权威状态存储后，审批单次终态、撤销可见性、持久交付和执行证据关联是否仍成立”的证据。发现的两项状态/审计问题属于这些治理义务，修复不涉及性能调优。资格结果支持所测实现与场景，不能直接等同于全部数据库或其他 Agent OS 的适用性。

下一步按六项契约核对剩余入口验证，冻结同一实现版本，完成 R0—R4 的八项共同场景及 R5 的两项组合检查。随后集中更新正文、入口出口分类、R1.1/R2.4答复、清洁稿和相对已投稿 v1.1.39 的累计修改稿。原11对象外部比较结果保持不变，不把本组资格用例并入独立业务样本数。
