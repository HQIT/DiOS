# OPA 调用上下文对照与独立工作负载盘点

2026-09-30。阶段小试，不是正式基准实验。论文、投稿 PDF 和后端产品文件本轮未修改，没有模型调用、远端部署或业务操作。

## 本轮结论

在同一宿主上将调用层判定器替换为独立 Rego 实现后，T01—T06、L01—L03九个共同用例与 E2AG 的执行结果一致；九项参数边界/反向策略控制也一致。两方法共36条运行均符合预期，但不能把控制项和方法重复计成36条独立业务样本。这支持“在已对齐的调用上下文与宿主机制下，OPA 可替换这一判定器”，不支持 E2AG 对 OPA 的安全优势。

另发现一项实验集成缺口：OPA 程序不可用时宿主拒绝执行，但原拒绝审计白名单不接受 `OPA_EVAL_ERROR`，因此没有新增调用审计。已单独保留故障轨迹，不将其算成正常策略拒绝，更不能宣布完整证据路径全部通过。

## 对照究竟替换了什么

| 部分 | 原 E2AG | E2AG-with-OPA 调用层小试 |
|---|---|---|
| 凭据鉴别、任务/能力读取 | 原生宿主 | 同一宿主；不把令牌交给OPA |
| 状态、期限、任务/能力对象关联判断 | Python 原生判定 | Rego 独立判断原始存储字段 |
| 工具集合、资源枚举和参数区间 | Python 原生判定 | Rego 独立规则，不调用E2AG判定函数 |
| 过期/终态引起的状态更新 | 原生宿主 | 宿主依Rego结果执行同样状态更新 |
| 强制拒绝、转发、审计、内存工具 | 原生宿主 | 同一宿主与工具替身 |
| 事件准入、来源鉴别、审批状态机 | 本轮预建任务，不作比较 | **尚未替换/验证**，不能称整条链路完整OPA比较 |

OPA 输入包括鉴别结果、可信时钟、能力状态/期限/工具集合/约束快照、任务及其关联标识、事件存储元数据和实际调用参数。事件元数据当前仅提供上下文，不代表已经在Rego执行来源契约准入。工具调用前分别进行 grant 与 call 阶段判定，生命周期拒绝会在第一阶段终止。状态由原生签发、撤销及真实数据库记录产生，不提前转换为共同“允许/拒绝”标签。

宿主从实际解析的参数生成类型事实，例如 `rows` 的 `int`/`float`/`bool`，不接受请求自行声明。这是为了对齐本协议区分 JSON 10 与10.0的约定，不是宿主先替OPA算参数是否合规。参数原文与类型事实均保存到小试轨迹；Rego再独立检查类型、取值和范围。配置只覆盖已验证的版本1约束；未经测试的 glob/fnmatch 方言、任意损坏配置、并发检查到使用的原子性不在等价性结论内。

驱动对原生 E2AG 判定函数设置失败哨兵：OPA 路径若调用它们即报错。配对校验检查相同业务输入、实际 receipt 内容、能力终态、调用计数和审计链；OPA 获得的输入不含预期标签、用例编号或令牌。参数拒绝的原因粒度不同（OPA统一参数拒绝，E2AG细分类型/枚举/区间），本轮只要求业务决策和实际执行一致，不声称解释文本完全相同。

## 结果与故障检查

| 用例组 | 观察结果 |
|---|---|
| T01、T06：普通合法请求/合法上界 | 双方均产生一个参数未改写的receipt |
| T02：集合外工具 | 双方拒绝，零receipt |
| T03—T05：资源、参数上限、类型违规 | 双方拒绝，零receipt |
| L01—L03：过期、撤销、任务trace关联异常 | 双方拒绝，零receipt；能力终态一致 |
| 九项诊断控制 | 双方均符合预期；与共同主用例分开统计 |

额外四项Rego上下文探测：任务主体不匹配、任务完成、鉴别失败、缺少时钟，均返回拒绝。这些仅为PDP检查，未提升为完整执行用例。另四项适配器故障注入（进程非零退出、未定义结果、结果格式错误、超时）均返回引擎错误并拒绝，不算业务策略判断成功。

真实进入共享代理的一次“本地OPA可执行文件不存在”故障也返回403且零receipt，但调用审计增量为0。原因是原宿主只为预设的能力状态拒绝记录调用审计；引擎故障的可持久化记录、错误分类和HTTP响应语义需在正式集成前处理。原始故障结果已保留，不能只展示36条正常运行来掩盖该问题。本轮未修改后端以扩大实验范围。

使用既有 OPA 1.17.0 Linux 程序，经WSL运行；哈希与旧OPA实验记录一致：`e83da46804832578e9d9e1733dffbe4d3b5f8cc9c26eb124da9ceea4abfe189f`。现存 `opa.exe` 无法在本机启动，未覆盖或修复它。未下载或升级引擎，未将命令启动耗时作为性能结果。调用与检查参数参照[OPA官方CLI文档](https://www.openpolicyagent.org/docs/cli)，Rego严格检查通过。旧构建信息中的 `-dirty` 字样原样留存，不擅自改写版本信息。
