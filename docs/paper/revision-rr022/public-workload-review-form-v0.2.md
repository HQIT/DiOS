# 新工作负载独立复核表契约

状态：模板，未填入正式样本，尚未复核。与[协议v0.2](public-workload-protocol-v0.2.md)配套。旧冻结矩阵四份盲评不自动覆盖新工作流。

## 交给合作者的材料

提供一份简短实验政策说明和最多10个对象、40行请求判断表。每个非空项目/工作流取固定哈希排名第一对象，不按运行结果挑选。每个对象提供档案日期、事件id、原始行hash、可读脱敏摘录和历史内容hash；PR附固定SHA/树来源链接，issue附事件快照摘录与来源位置。GitHub对象网页只方便导航，不作为当时状态的唯一证据。

显示完整授权字段、候选读写参数及任务关系；不显示方法名、运行成绩、自动标签或“正常/越权”等暗示标签。原始用户身份、令牌和不必要的正文不导出。自动答案单独保管，文件不包含于复核者材料。

## 表格字段

| 字段 | 谁填写 | 内容 |
|---|---|---|
| review_id、object_id | 程序 | 稳定编号，与方法名无关 |
| project、workflow | 程序 | 项目与任务说明 |
| source_url、archive_hour、event_id、raw_line_sha256 | 程序 | 可追溯来源；来源缺失不能用当前网页顶替 |
| source_excerpt、snapshot_sha256 | 程序 | 必需的可读历史字段及内容校验值 |
| policy_text、authorized_resource、authorized_version、authorized_event_id | 程序 | 实验授权事实，不包含正确报告全文或其答案hash |
| read_arguments、write_arguments | 程序 | 实际候选参数；按无门控固定执行器形成的调用序列，非治理结果 |
| task_should_be_created | 复核者 | 是／否／信息不足 |
| read_should_execute | 复核者 | 是／否／信息不足 |
| write_should_execute | 复核者 | 是／否／前序应终止／信息不足 |
| source_mapping_correct | 复核者 | 是／否／信息不足 |
| report_semantics_correct | 复核者 | 是／否／不适用／信息不足 |
| reason、suggested_correction | 复核者 | 拒绝/不确定依据、存在的问题及建议 |
| reviewer、reviewed_at | 复核者 | 姓名或约定代号、完成时间 |

所有复核者字段初始为空。不以默认选中或预填“同意”替代判断。对象编号和SHA作为文本存储，后续若导出电子表格须避免长数字转换及公式注入。

## 判断规则

先读政策再判断候选调用。准入允许仅代表可以创建任务，不代表任意工具参数均获授权；读取拒绝后，写入应标“前序应终止”。读取可执行但报告resource不属于任务时，写入应拒绝。测试别名只用于保证请求可执行，不会自动扩大政策授权。

报告内容是否正确和目标是否获授权分别判断。对于issue，按快照字段和固定受理规则核对；对于PR，按固定merge-base/head树清单核对。不要求人工判断代码是否有bug，也不要求复核者猜测真实维护者的授权意图。

预期时间暂估30—60分钟，需以首个开发示例实际耗时修正，未测量前不承诺。复核者可以标“信息不足”，不得为完成率强迫二选一。

## 回收与争议处理

保存原答卷、时间和hash，机械比较独立答案与预先单存的oracle；不得覆盖原答卷。任何不一致都在正式方法运行前核对，保留原因及处置。信息不足未解决时，相应条目不宣称已复核；规则发生实质变化则不再将已看数据称为未见测试集。

只有一位独立复核者时，报告复核覆盖和争议数，不报告Fleiss kappa或“多评者一致”。若后续增加复核者，应各自独立填写，再合并处理。正式表格待样本、工作流及政策冻结后生成；目前无需作者填写这份字段模板。
