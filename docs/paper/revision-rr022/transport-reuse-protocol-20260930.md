# 底层连接复用单因素开发对照

先保存实现与协议，再运行。目的：检查逐调用HTTP传输初始化与连接重建是否构成可削减的实现成本，以及改变这一个因素后SQLite锁失败是否仍存在。不是新治理算法，也不是正式性能结果。

实现以可选开关控制POST代理的底层传输生命周期：对照为每次调用新建并关闭传输；干预为每个应用worker的lifespan创建/关闭共享传输，每次请求仍使用独立AsyncClient及Cookie容器。请求头逐次构造，不能放进共享客户端默认头；MCP会话编号只按当前请求转发。连接池按HTTPX默认的100总连接、20空闲连接及5秒空闲过期配置，TLS校验开启、环境代理关闭、30秒超时、原重定向行为和零传输自动重试保持不变。应用配置默认关闭，远端不部署；GET/SSE和DELETE保持原路径。

正确性门槛包括：真实socket复用的连接端口证据；顺序和并发请求的认证头/会话编号隔离；上游Set-Cookie不进入下一请求；应用退出关闭连接池；每次调用仍校验能力和工具；原三种持久化故障（意图、读取结果、写入结果提交失败）在复用模式下复验。持久化步骤、业务参数、规则与外部对照均不变。

先用既有开发issue、G2、并发1及8各做一个模式配对，2秒预热、8秒测量，两个模式的先后顺序预先固定并在结果首部记录，不依结果挑选顺序。每格新数据库和新进程。沿用全机15%可用内存、5%基础设施错误率持续10秒等原停止阈值：触发时停止该格，配对中如某模式未过，仍允许另一个模式独立做同一有界格，用于定位，不称通过完整矩阵。记录所有失败、未执行格及资源状态。

正确性门槛通过后，再以共享传输模式运行原18格（两输入×G0/G1/G2×并发1/8/32），原固定顺序与停止规则不变。G0/G1实际不创建代理连接池。新增意图事务成本仍计入G2；启动时传输/TLS初始化单列记录，不算“消失”，稳态与冷启动不混淆。禁止在计时期间并行跑其他本任务测试。

同机短轮次、有限请求及顺序效应只允许形成实现优化的局部观察；不能估计生产容量或稳定尾延迟。该单因素同时改变TLS上下文初始化频率和连接复用，若无进一步拆分，不能把收益全部归因于网络握手，也不能断言已证明锁失败的唯一根因。正式长测与独立留出比较继续等待各自验收条件。
