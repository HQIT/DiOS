# 受控 stdio 工具传输资格检查

2026-10-07。对应[精简方案 v0.3](heterogeneity-protocol-v0.3-20261007.md)的工具传输替换资格。8项共同治理场景及独立证据核验通过；后端114项测试、65个子检查通过，其中新增13项 stdio 回归。该组采用文件入口隔离检查工具传输，尚不是正式 R3 的 HTTP 事件入口配对结果。

## 适配位置和机制

原实现仅代理 Streamable HTTP，enforce 模式下不向任务提供 stdio 配置。本次增加显式启用的受控 stdio 路径：管理员通过 `e2ag_stdio_server_ids` 指定允许的工具服务，空列表为默认值。任务仍只获得任务作用域代理地址和凭据，不获得工具可执行文件、参数或环境配置。未列入允许清单的 stdio 服务保持禁用。

调用沿用原有能力校验、工具及参数策略、持久调用意图、结果记录和审计逻辑。仅在授权通过并保存调用意图后，代理将 JSON-RPC 请求写入该能力对应子进程的标准输入，并从标准输出读取响应。可执行文件必须是管理员配置的绝对文件路径，不使用 shell 拼接请求参数；子进程不默认继承模型或应用凭据。一个能力对应一个会话和子进程，启动、初始化、调用及关闭由应用进程管理。

消息采用 UTF-8 JSON、换行分帧，同一子进程依次接收 initialize、notifications/initialized 和工具调用。验证响应标识与请求标识一致；无法解析的响应、超时或进程退出不触发自动工具重试。传输与生命周期要求参照 MCP 2025-06-18 的[传输规范](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports)和[生命周期规范](https://modelcontextprotocol.io/specification/2025-06-18/basic/lifecycle)。当前实现为工具调用子集，不转发服务端发起的 sampling、roots 或 elicitation 请求，客户端初始化能力集合限定为空。

## 共同治理场景

复用文件资格组的原生订阅、事件准入、任务创建、审批、能力签发与撤销路径。固定执行器仍替代 DiAgent 容器和模型，客户端通过 ASGI 进入原生代理；代理到工具实际使用 OS 子进程管道，而非 HTTP 工具或模拟响应。数据库为各场景独立的磁盘 SQLite。

| 场景 | 观察结果 |
|---|---|
| G01 正常执行、G04 批准后执行 | 各生成一个内容正确的产物；重复事件不增加任务或写入 |
| G02 来源拒绝、G03 待审批 | 零工具子进程、零工具请求；审批状态持久保留 |
| G05 未授权工具、G06 越界资源 | 调用 PEP 明确拒绝；工具进程仅接收初始化，不接收违规工具调用 |
| G07 撤销、G08 过期 | 新调用被拒绝，实际工具端零对应请求；拒绝原因和能力关联可核对 |

8项场景全部满足预期，只有正常与获批两项产生工具写入，不能把“8项通过”解释为8次业务执行成功。独立检查程序直接读取磁盘数据库、审计链、请求接收文件及产物，再核对 stdio 消息序列、PID 和启动/退出记录；检查无失败。6个需要任务执行的场景均在同一子进程中完成初始化并在结束时退出。34次工作进程是阶段隔离，不作为独立业务样本数。

运行前冻结73个 Python 源文件，运行结束后指纹无变化。本组资格结果、冻结清单、各场景数据库、原始管道消息和产物保存在 `experiments/e2ag/heterogeneity/results/stdio-qualification-20261007-v1/`，独立检查结果为 `audit-v1.json`。

## 故障和生命周期回归

另新增13项回归，使用真实子进程和管道、原生调用 PEP及隔离内存数据库。它们是支持性回归，不加入上述8项持久场景的样本统计。

检查覆盖同进程初始化与调用、拒绝工具和错误凭据不启动进程、未初始化调用不隐式启动、撤销后重新连接拒绝、未启用服务不下发配置、调用意图提交失败不向管道转发，以及结果提交失败后保留 unknown。对工具已写入后退出、超时、返回畸形响应或错误请求标识四种条件，均只观察到一次写入，调用保持 `outcome_unknown`、无自动重试。关闭检查确认回收子进程；相对可执行路径拒绝。

全部 `test_e2ag*.py` 共114项测试及65个子检查通过，JUnit 记录为 `experiments/e2ag/heterogeneity/results/stdio-regression-20261007-v1.xml`。首次单文件运行还收集了导入的既有测试类；后续移除该收集重复，全量114项统计没有将其重复计数。`git diff --check` 通过。

## 代码和适用范围

新增核心适配器为 `backend/app/services/e2ag_stdio_transport.py`；调用路由、能力配置签发、应用生命周期和配置类增加必要接入点。旧 HTTP 分支保留，未部署到远程测试服务器，未修改默认允许清单。修改前文件保存在 `tmp/heterogeneity-prechange-20261007/stdio-20261007-152348/`。

资格运行器为 `experiments/e2ag/heterogeneity/run_stdio_qualification.py`，共用工作进程为 `run_file_recovery.py`，工具为 `stdio_receipt_tool.py`；核验入口为 `check_stdio_qualification.py`，复用只读数据库/审计核验函数并增加管道和生命周期核对。13项回归位于 `backend/tests/test_e2ag_stdio_transport.py`。

这一结果支持受控代理更换为所测 stdio 工具后仍执行同一授权约束。前提是管理员配置可信、单个应用进程持有会话、工具启动属于受控运行环境；没有授予 Agent 任意本地进程启动权限，也未验证多工作进程之间的 stdio 会话迁移。会话数有显式上限，不据此作长时间运行容量结论。工具内部任意文件或网络访问仍不是本实验的控制对象。

下一项完成 PostgreSQL 的审批、撤销和持久交付资格检查，然后冻结同版本 R0—R4 主配置及 R5 两项组合。正文、入口出口分类、R1.1/R2.4答复与累计修改 PDF 在正式结果稳定后一起同步，不能继续把“所有 stdio 均禁用”当作新实现的完整描述，也不能提前写成全部异构建议已完成。
