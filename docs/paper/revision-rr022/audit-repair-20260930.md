2026-09-30。结论：已修复本轮确认的、可鉴别归属的 POST 工具调用拒绝审计缺口；授权结果不变，未增加任何放行条件。原始缺口证据保留，论文正文与已投稿 PDF 不变。

## 修复及边界

真实代理在 `validate_grant` 拒绝后调用新增 `record_grant_rejection`，只处理非活动、过期、任务关联异常和任务终态等已知原因。记录前重新核验令牌，并确认能力保存的事件与 trace 相符。审计使用能力里的任务/事件归属，不采信请求自行声明的身份；不记录令牌、工具参数或请求体。

对未知 ID、无效/空令牌、另一授权的令牌、缺失或不一致的事件归属，不向该事件链写入归属不明的内容。其通用入口安全日志尚未在本补丁实现。因此不能把本修复表述成“所有输入、所有拒绝都拥有完整审计”。GET/DELETE、无效 JSON、审计并发追加与状态变化/调用记录跨事务原子性均不在此次新增验证范围。

拒绝调用记录仍是拒绝证据，不是执行许可。审计写入异常会向上抛出且不转发工具；尚未新增专门的审计故障 HTTP 错误转换。`call_count` 对已鉴别、可归属的 tools/call 拒绝尝试增加1，含义是尝试次数，不是实际执行次数。

## 回答“是否已经优于 AgentSpec”

没有。已完成的5个共同用例（工具2例、审批3例）中，两种方法都符合预期。本次修复关闭的是 E2AG 自身工程缺口，不构成新颖性或比较优势，也不能将修复前后的差异算成外部方法劣势。

后续保留三类可证伪问题，不预设胜负：

| 问题 | 公平比较方式 | 判断边界 |
|---|---|---|
| 调用前业务规则是否正确执行 | 相同输入、上下文和工具，AgentSpec 原生规则与 E2AG 对齐；补参数/资源约束 | 双方相同则报告相同，不追求人为成功率差距 |
| 跨层授权状态如何落实 | 与 Agent libOS 对齐过期/撤销及可对应的主体绑定；AgentSpec 新增状态集成单列 | 未接入不算失败；不把 libOS 主体绑定冒充相同 trace 模型 |
| 完整链路与证据组织是否有增量价值 | 独立工作负载、授权前驱/拒绝定位证据、完整上下文 OPA及完整路径开销 | 普通集成即可达到相同效果时收缩创新主张；不能用代码行数或“对方无Connector”直接证明优越 |

下一步继续生命周期外部对照与参数/资源共同规则接入。跨层、生命周期和审计“可能有价值”仍是待验证假设，不提前写入摘要或回复为既成优势。
