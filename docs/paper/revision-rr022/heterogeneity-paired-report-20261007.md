# 异构接入、工具传输与事务存储配对报告

2026-10-07。按照作者批准的[精简方案 v0.3](heterogeneity-protocol-v0.3-20261007.md)，完成五组主配置各8项共同场景，以及两项组合检查，共42项配置—场景配对。独立持久记录、传输记录和工具产物核验通过。该组检查治理机制对适配方式变化的一致性，不增加独立业务样本或模型样本。

## 问题、配置与控制条件

所回答的问题是：保留同一来源准入、任务能力和调用约束，在替换事件交付机制、工具传输和权威状态存储后，正常业务、拒绝/审批状态及执行证据能否保持一致？R0为同版本参照；R1—R4分别只替换一个因素；R5检验两项指定组合，不穷举所有组合。

| 配置 | 事件接入 | 代理至工具 | 权威状态 | 完成情况 |
|---|---|---|---|---|
| R0 | 签名 HTTP Webhook | MCP Streamable HTTP | SQLite | 8项符合预期 |
| R1 | AMQP 0-9-1 消费 | MCP Streamable HTTP | SQLite | 8项符合预期 |
| R2 | 文件投递箱 | MCP Streamable HTTP | SQLite | 8项符合预期 |
| R3 | 签名 HTTP Webhook | 受控 MCP stdio | SQLite | 8项符合预期 |
| R4 | 签名 HTTP Webhook | MCP Streamable HTTP | PostgreSQL | 8项符合预期 |
| R5 | AMQP 0-9-1 消费 | 受控 MCP stdio | PostgreSQL | 2项组合符合预期 |

三个入口均使用实际接口：回环 HTTP 请求、真实消息代理交付和完成发布后的文件读取。它们是实验适配器，接入相同的原生 DiOS 订阅、调度、审批、能力和调用 PEP；不是三个成熟产品 Connector 的完整部署。事件信封统一保存交付标识、业务载荷和内容摘要，来源由端点、队列或投递目录的可信配置绑定。授权字段在三种格式转换后保持一致。

各场景使用独立数据库，同一固定业务任务将输入文本转为大写并写入获准报告对象。上游工具会记录所有实际收到的工具请求，不以工具端拒绝掩盖治理失败。任务容器启动由固定执行器替代，客户端至 PEP 为 ASGI；代理至工具为真实 HTTP 或 OS 子进程管道。没有新增模型调用。RabbitMQ为3.13.7，PostgreSQL为16.13，依赖与镜像固定信息随结果保存；运行在隔离本地环境，不改动远程实例。

## 主配置结果

R0—R4逐场景执行结果一致。正常场景和批准后执行场景分别产生一个内容正确的报告；来源不满足约束时不创建任务，待审批时不创建任务或工具请求。合法任务提出未授权工具、范围外资源、已撤销能力或已过期能力请求时，均由调用 PEP 明确拒绝，上游没有收到对应工具调用。每项实际重复交付后，任务和报告数量均不增加。

| 每个主配置的结果 | 数量 | 实际观测 |
|---|---:|---|
| 正常与批准后业务 | 2/2完成 | 两份正确产物，各写入一次 |
| 来源拒绝 | 1/1符合规则 | 零任务、零工具请求 |
| 待审批 | 1/1保持等待 | 一份 pending 审批，零任务、零工具请求 |
| 工具、资源、撤销、过期拒绝 | 4/4符合规则 | 返回明确拒绝原因，零对应工具写入 |

五个主配置合计40个事件、30个任务、10份审批和10次工具写入。每配置14条已转发记录包含初始化及初始化完成通知，不能解释为14次业务工具调用。独立检查同时核对事件与任务、任务与能力、能力与调用意图、审批与事件，以及哈希链和实际产物，避免将“全部拒绝”或仅有运行器通过标志当作实验成功。

## 两项组合结果

J01在事件进入待审批状态并持久完成交付后终止消费者，但不确认代理消息。新消费者收到实际重投递，依据原记录完成确认；随后提交固定批准操作。SQL、代理记录和工具产物共同表明：一份审批进入 approved，一个任务执行，一份报告写入；再次批准返回 `APPROVAL_ALREADY_DECIDED`，重复交付没有新增任务。

J02在能力撤销提交后关闭原 stdio 会话，再请求初始化和工具调用。两次请求均返回403及 `TOOL_GRANT_NOT_ACTIVE`；未启动新工具子进程，也没有新的工具写入。该结果说明撤销后的重连尝试不能恢复执行权，不表示允许建立新会话后才在工具内部拒绝请求。

42项合计42个事件、32个任务、32个能力、11份审批、11次实际工具写入。75条转发记录中，64条是初始化或通知，11条是获准工具调用；不把这些控制消息或181个阶段工作进程计为独立业务样本。

## 解释与论文修订落点

直接请求、代理消息和文件发布的交付/恢复边界不同，但三者将相同授权字段映射到规范事件后，仍由同一准入和调用检查限制执行。工具传输替换发生在能力校验与持久调用意图之后；状态后端替换则保持条件更新、对象绑定和证据追加义务。上述机制解释了本组一致结果，其依据是明确接口契约而不是平台名称不同。

这组结果补强R1.1的三类环境维度和R2.4的受控stdio出口说明，并补充R2.2有关A1—A3工程义务的证据。共同场景是固定构造输入，所用适配器由研究团队实现；外部有效性仍受一个Agent OS、固定执行器、可信入口配置和所测故障切点限制。文件不可变发布、单消费者恢复权及服务凭据隔离属于前提；未验证第二个完整Agent OS，也没有获得外部基线效果优势。
