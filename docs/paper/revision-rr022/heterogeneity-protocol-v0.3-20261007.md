# 异构治理验证 v0.3：精简范围与验收矩阵

2026-10-07。作者已确认本范围。覆盖 v0.1/v0.2 的后续执行安排；旧文件、结果及 IMAP 修复保留。本文档固定实验义务，具体实现、源码哈希与正式运行清单待资格检查结束后冻结。尚无本组正式端到端结果。

## 选择与主张

接入保留 HTTP Webhook、AMQP 0-9-1 和文件投递箱；工具传输保留 MCP Streamable HTTP/stdio；权威状态采用嵌入式事务存储/服务式事务存储，分别以 SQLite/PostgreSQL 实现。AMQP 使用隔离 Broker，文件来自受控目录，具体依赖版本随执行冻结。

选择的依据是直接请求、消息代理交付、非网络文件交付所涉及的身份、交付和恢复边界不同，不将三者称为穷尽所有 Connector 的分类。退出 IMAP 正式实验，其修复与测试仅作历史回归；不增加追加文件审计后端、第二 Agent OS 或性能优化。

本组支撑的主张是：在明确适配契约和信任前提下，所测替换配置保持既有准入、能力约束及证据关联。不能由本组推出所有协议/全部组合有效，也不能推出对外部基线的效果优势。

## 契约覆盖矩阵

| 契约 | 必测条件 | 预期证据 | 适用配置 |
|---|---|---|---|
| 来源绑定 | 合法来源；错误凭据或未授权投递位置；载荷自报其他来源 | 实际接入身份与规范事件来源一致；不合法输入零任务；拒绝原因可核对 | R0—R4，按入口分别实现 |
| 事件转换 | 正常载荷；缺字段/畸形载荷；额外保留字段；授权相关字段转换前后比较 | 规范化映射记录；畸形输入不进入任务创建；不能覆盖受控来源 | R0—R4 |
| 事件身份 | 新标识；相同标识相同内容重复交付；相同标识不同内容；同内容不同标识 | 事件/任务 ID 与计数；冲突显式报告，不静默覆盖旧内容 | R0—R4 |
| 交付与恢复 | 接收记录提交前失败；提交后交付确认丢失；重新连接/应用重启 | 交付记录与持久状态对照；不把确认当业务成功；恢复不绕过治理 | R0—R4，按机制选注入点 |
| 强制准入和调用 | G01—G08 核心场景；首次和恢复路径 | 准入及调用判定、任务/能力绑定、独立工具接收记录、业务产物 | R0—R4 |
| 证据关联 | 正常链；接收记录失败；调用意图失败；响应丢失；结果记录失败 | 记录可归属；意图提交失败零转发；已可能执行而无响应标记 unknown；不自动重试写入 | R0—R4 |

这六项是本文治理契约的测试义务，不是协议通用标准。共享核心逻辑的边界测试可以复用，但每个适配器均须有真实接口到核心的连通和字段保持检查；mock 结果不计作真实链路证据。无网络的文件入口检查目录授权/路径边界，不伪造“错误网络密码”用例。

### 八项共同治理场景

| ID | 条件 | 必须观察到的结果 |
|---|---|---|
| G01 | 来源和任务、工具、资源均获准 | 业务产物正确且证据可关联 |
| G02 | 来源不满足目标准入约束 | 零任务、零工具请求，准入拒绝有据 |
| G03 | 任务需要审批但未批准 | 待审批状态持久化，零工具请求 |
| G04 | 与 G03 同类任务获批 | 单次有效审批转换，业务正常完成 |
| G05 | 合法任务请求未授权工具 | 调用 PEP 拒绝，工具端无对应请求 |
| G06 | 合法任务请求授权范围外资源 | 调用 PEP 拒绝，工具端无对应请求 |
| G07 | 已签发能力被撤销后新调用 | 新调用拒绝，撤销状态与证据关联 |
| G08 | 已签发能力到期后新调用 | 新调用拒绝；记录服务端时间及有效期 |

G03 不人为补发能力以绕过待审批状态。G07 的撤销指提交生效后开始的新调用，不暗含撤回已在执行的操作。G01/G04 同时评价可用性，防止全部拒绝造成虚假安全。

### 机制特有检查

HTTP：签名/请求凭据与载荷绑定，客户端未收到响应后的重投递。

AMQP：手动确认；未确认断连后的重投递；策略拒绝持久记录后终结该次交付；存储故障不提前确认。消息来源来自受控队列与生产者权限边界，不信任自报 source。

文件：只扫描已完成发布的 ready 文件；临时/半写文件不得创建任务；拒绝目录外路径、链接/重解析点及非法格式；重复扫描和重启不重复触发。生产者同文件系统发布后不得改写文件，OS 权限和配置由可信管理员控制。不能把事后文件时间检查当作对任意恶意并发文件改写的安全证明。

存储：审批单次终态、持久认领、撤销新会话可见性、应用重启后恢复；两会话竞争只验证状态转换，不作吞吐测试。新库结果不代表生产迁移得到验证。

R5 只测 J01“待审批事件重投递＋消费者恢复，随后单次审批并执行”和 J02“撤销生效＋工具链路重连后的新调用”。与参照结果比对以检查组合衔接，不外推全组合兼容。

## 执行与停止条件

先实现必要适配并完成资格检查，冻结所有条件、预期与版本后运行正式组。资格阶段缺陷、修复和回归单列。对每个覆盖项记录通过、失败、未执行或明确不适用，不以计划数量代替已执行数量，不为通过率删掉失败。

实验结果需包含配置、场景、输入指纹、源码版本、实际判定、任务/能力/调用关联、工具端记录和业务产物。对确认丢失和 unknown 等情况分别报告授权安全、完成情况与可恢复性，不合并为一个成功率。

先完成文件适配的输入与准入检查，再推进隔离 AMQP、stdio、PostgreSQL；最后用同版本 R0 作配对参照。正文和 R1.1 回复待结果稳定后统一修改，旧 11 对象正式比较不重写、不覆盖。覆盖矩阵出现不能落实的条件时记录缺口并评估其对主张的影响，不自动扩成新的研究课题。
