# 资源与参数约束：修改前后配对小试

2026-09-30。阶段结论：审稿人指出的细粒度缺口确实存在，现已实现并验证一个有边界的扩展。AgentSpec 按官方扩展接口配置后能执行相同规则；新增结果不支持 E2AG 的拦截优势，不作为独立创新证据。正文和已投稿 v1.1.39 PDF 未改，未部署到远端。

## 设计与公平性

复用冻结的 `common-cases-v0.1.json` 中 T01—T06：合法工具为 `report.create`，资源标识精确等于 `repo/qame/report/a`，rows 必须为整数且处于1—100，bool和float不作整数转换。参数对象采用封闭字段集合，resource、rows均必填，其他字段拒绝。这是协议中 unknown/missing deny 在本轮的具体实现，不声称兼容任意 JSON Schema。

两个方法接受相同原始调用和业务规范，预期结果仅由父驱动持有。AgentSpec 使用独立编写的 Python 业务谓词；E2AG 使用通用字符串枚举、整数区间检查器。两者不共享判定代码，只有规范和无条件追加内存 receipt 的工具替身相同。工具自身不检查权限，禁止用工具端自拒绝冒充治理拒绝。

AgentSpec 固定于 `e6fa3902e2cfb9681f454b355691b771f70543f8`，依据其 README 的 Predicate Definition/Registering the Predicate 接入：语法只新增 `rr022_argument_violation`，用仓库自带 ANTLR 4.13.2 jar 和现有 WSL Java 生成独立解析器目录，再向原生 `predicate_table` 注册函数。原生解释器、stop 执行机制和 ControlledAgentExecutor 不改；继续使用此前单独审计过的 finish 兼容类。生成目录、命令、Java版本和文件哈希随原始结果保存，原仓库没有源代码修改。这属于“官方框架＋披露的业务规则配置”，不是论文作者原有内置规则。

E2AG 先运行未扩展的能力签发/数据库/调用代理，再增加能力字段并使用同一驱动重跑。两次驱动、用例、辅助脚本、任务输入、规则和各方法依赖一致；校验器验证这些条件，AgentSpec 两轮行为不变。预加载事件与任务、固定模型调用输出，仅替换出站 MCP 为内存工具；没有真实网络端点、模型生成或性能测量。

“执行一次”指工具回调确实新增一个内存 receipt，含未经改写的工具名与参数，并非驱动根据预期填入的计数。修改前 E2AG 的三次放行如实保留，不记成实验脚本异常，也不从结果中删除。

另外单列9项诊断控制：下界1、0、bool、float、缺字段、额外字段、null，以及改变授权资源和上限后的正反两项策略控制。扩展后双方均符合预期；反向控制验证实现不是固定写死原资源和100阈值。这些控制不是9条独立业务样本。30条“方法×输入”运行不能称为30条真实任务或安全成功率。

## E2AG 最小扩展及边界

在可信宿主配置 `Agent.capabilities.governance.argument_constraints` 中声明规则，签发时校验格式并深拷贝到 `E2AGToolGrant.argument_constraints`，调用时读取该快照，而不读取可能已扩大的 Agent 当前配置。例如：

```json
{"version":1,"tools":{"report.create":{
  "resource":{"type":"string","enum":["repo/qame/report/a"]},
  "rows":{"type":"integer","minimum":1,"maximum":100}
}}}
```

规则只有顶层必填字段、字符串精确枚举、整数闭区间；已启用约束的能力中，未配置具体工具、缺失/未知字段、类型错误、范围不匹配均拒绝。新增格式版本、未知配置项、显式null或错误配置不能静默跳过：签发时不发能力，调用时若快照格式损坏则拒绝。工具集合、期限、撤销和任务关联检查仍先于参数授权。

拒绝进入原生调用审计，包含原因、任务/能力绑定及规则快照 SHA-256；不记录原始业务参数或令牌。规则摘要不是签名，也不是参数完整证据：仅有审计记录不足以重建原始参数，实验原始轨迹另行保存了合成输入。快照依赖可信数据库与宿主配置，不能被描述为抗数据库管理员篡改。

资源在本轮只是规范化业务标识的精确字符串匹配，不解析文件路径、符号链接、URL别名或工具内部二次资源选择；无法代替资源解析器和信息流控制。不能由这组结果声称解决敏感数据传播或所有合法工具内部违规。

兼容和部署义务：未设置此配置的旧能力仍为工具级约束，不自动获得参数防护；旧数据库迁移只新增可空列，不重写已有授权。若业务要求全面启用，须配置、撤销旧能力并重新签发。已验证 SQLite 旧表迁移幂等性，未做现有 PostgreSQL 数据库迁移或现场部署；非SQLite旧库应先完成显式模式迁移。修改 Agent 配置不会自动撤销历史能力，需要原有生命周期操作。
