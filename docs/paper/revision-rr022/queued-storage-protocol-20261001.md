# 实验持久化基础设施统一方案

2026-10-01。依据作者本轮意见，停止将SQLite竞争作为研究问题深入优化，采用现成的异步数据库连接池完成事务排队；不新增治理机制，不更换数据库，不修改生产默认配置或部署远端。

实施限定在实验运行器。原池配置为5个常驻连接、最多10个溢出连接；新配置为1个连接、0个溢出连接。两者连接池等待上限均为30秒，SQLite busy timeout仍为5秒，DELETE/FULL持久性设置、HTTP超时和原资源停止阈值均不变。异步排队不会阻塞事件循环，但会串行化读取和写入事务；它不是只对写语句加锁，也不是不计代价的优化。排队等待完整计入客户端工作流耗时。

G0、G1、G2全部使用相同池设置，不只给完整方法使用。前轮共享HTTP传输在G2保持开启，G0/G1维持原直连。存储提交、回滚、调用前意图、调用后结果及未知状态语义保持不变。队列授予事务连接，不包住整个任务；外部HTTP工具调用必须在该请求数据库事务结束后进行，并以服务端观测核验。应用单worker、单进程连接池的范围如实披露，不声称解决多进程或分布式一致性。

先验收5项基础设施测试（32事务更新、排队取消、回滚、提交后释放及配置检查）和既有6项计时器测试；再在新设置下运行原三个真实HTTP持久化故障场景及单请求资格检查。通过后运行原18格短预试验，不在计时期间并行运行本任务其他测试，不更换输入、不删除失败配置、不放宽阈值。记录峰值连接占用必须为1、结束占用为0，并检查工具调用前没有本请求未结束的数据库事务。

本轮目标是让现有研究实验能够公平、可靠地运行，不是证明队列或SQLite具有研究创新。旧失败结果、代码备份和源码冻结均保留，新结果另存。正式留出比较仍等待独立复核；短预试验完成不等于长测完成，也不生成新的论文性能结论。若仍出现非存储故障，记录为环境/适配边界，不再沿SQLite优化方向扩展研究范围。

资格检查修正：故障检查v1使用10毫秒请求启动窗口，实际调度耗时约20毫秒，未启动任何请求，故中止；保留其空结果与临时记录，不作为故障实验结果。v2改为固定一条请求、并发1、无预热，与时间窗口无关；此选项只用于故障资格检查，不应用于任何性能配置。11项基础测试、三个故障场景及单请求完整流程通过后，才启动18格短预试验。
