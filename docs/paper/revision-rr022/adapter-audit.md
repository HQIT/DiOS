# AgentSpec 兼容适配明细

日期：2026-09-29。适配对象为作者仓库提交 `e6fa3902e2cfb9681f454b355691b771f70543f8`。没有修改或重新分发上游源码。

## 实际只有一处行为适配

本地脚本 `experiments/e2ag/rr022/run_agentspec_smoke.py` 第51—55行的 `FinishCompatibleRule.triggered`：

```python
if action_name == "finish" and input is None and self.event not in {"finish", "any"}:
    return False
return super().triggered(action_name, input)
```

原因：作者 `Action.from_langchain` 将任务结束对象转换为 `Action(name="finish", input=None, ...)`，而工具规则的 `Rule.triggered` 会在名称不匹配时继续调用 `input.strip()`，产生 AttributeError。

处理含义：一个没有工具参数的任务结束，不应匹配其他工具的前缀触发条件。这里只把该情形视为规则不触发，不伪造允许判定，不执行任何工具。显式 finish/any 规则仍交给原方法；普通工具动作、谓词判定、stop/skip、人工询问与工具执行均未重写。脚本默认不启用，只有 `--finish-compat` 才启用，并在结果记录开关。

这不是无条件忽略异常：工具动作的 None 或字典参数等其他输入仍可能报原有错误，适配不会将它们放行。结构化工具参数转换属于下一阶段需要明确设计的输入适配，不在这次完成范围内。`any` 的检查是 Rule API 层检查，不宣称当前 DSL 的所有事件 token 都可解析。

## 与测试设置的区别

| 项目 | 实际做法 | 分类 |
|---|---|---|
| 任务结束空值处理 | 上述独立 Rule 子类，作者代码不动 | 唯一行为兼容适配 |
| 固定动作规划器 | 不调用模型，给执行器预定动作及任务结束对象 | 实验控制，不是 AgentSpec 的模型能力 |
| 内存工具 | 只增加 receipt 计数，不操作真实资源 | 安全测试端点 |
| 审批 yes/no | 在原生询问发生时由脚本回答，同时确认回答前没有工具调用 | 自动化夹具，不是持久审批实现 |
| 补齐动作历史 | 给原生谓词提供其规范要求的成功拾取观察 | 修正我们遗漏的输入，不改对方规则 |
| LangChain 等依赖版本 | 两个隔离虚拟环境，精确版本在结果中 | 环境配置 |
| Agent libOS socketpair 放行 | 允许 Windows asyncio 的内部回环通道，其他连接仍禁用 | 修正我们断网保护的环境误拦，不改 libOS |

## 验证与边界

1. 原规则与兼容规则下，8项单步执行检查的工具调用次数和通过结果一致。
2. 原规则的完整任务完成探针报错；兼容规则完整完成，工具仅调用一次。
3. 新增 `audit_agentspec_compat.py` 从实际小试脚本提取该类进行差分检查，不另外手写一个替代版本。覆盖4种规则事件 × 3种动作 × 4种输入，共48组：46组保持相同返回值或相同异常；2组仅发生预期的空值结束行为变化；48项边界预期全部符合。

结果：`experiments/e2ag/rr022/results/agentspec-compat-audit-20260929-v1.json`，包含逐项输入、前后返回/异常、预期变化标记与脚本哈希。这是有限边界检查，不能称为所有可能输入上的等价证明，也不能计作新的独立业务样本或安全率。

正式论文若使用适配后版本，应注明“作者原实现＋任务结束兼容适配”，给出原提交、适配内容与验证记录。不能写成完全未经改动的原系统复现，也不能把原版本完成错误作为安全劣势。
