# E2AG 外部 OPA 工具边界基线实验报告（2026-08-16）

## 1. 目的与公平性口径

本实验检验独立公开策略引擎在只观察工具边界对象时可以覆盖哪些跨层治理情形。基线采用官方 Open Policy Agent（OPA）v1.17.0，不调用 E2AG 判定代码。主比较从60例冻结矩阵中按结构规则选取49例“可调用”用例：目标非空、事件显式声明 `requested_tool`，且目标策略含 `allowed_tools`。其中正常30例、跨层违规19例。其余11例在形成可比较工具授权对象前已终止或未声明工具，明确排除；把这些用例直接计为 OPA 拒绝会虚增工具边界覆盖。

OPA-Tool 只接收 MCP 方法、工具名和逐例任务允许集合，不接收事件来源、目标动作、审批及能力生命周期。实验比较的是输入可见性与保护对象，不评价 OPA 通用引擎的能力上限，也不比较本地时延。若提供完整跨层对象和相应策略，OPA 可以作为 E2AG 的 PDP。

## 3. 结果

| 方法 | 正常通过 | 违规非允许 | 总体对齐 |
|---|---:|---:|---:|
| NoGuard | 30/30 | 0/19 | 30/49 |
| OPA-Tool v1.17.0 | 30/30 | 4/19 | 34/49 |
| E2AG | 30/30 | 19/19 | 49/49 |

OPA-Tool 保持30/30正常调用，并对19例违规中的4例返回非允许。这4例都是调用边界可直接观察的工具集合不匹配；其余15例的工具名本身在允许集合中，违规信息位于来源、事件类型、目标动作或审批状态。完整 E2AG 通过调度前 PEP 补充这些上下文，因而在相同切片上得到19/19非允许。差异来自策略输入和 PEP 布置，不表示 OPA 执行引擎本身弱于 E2AG。

为验证工具集合判定语义，另保留10例接口补充集：8例 `tools/call` 中，OPA-Tool 与 RuntimeGuard 均正确处理4例集合内和4例集合外工具；2例非 `tools/call` 方法用于检验 MCP 方法中介，不计入该补充比较。

## 4. 对论文主张的影响

论文可以给出一个可复核的独立引擎参照：通用 PDP 可以执行任务级工具集合规则，但只给工具边界对象不足以判断跨层授权是否合法。E2AG 的研究内容是构造并传播事件--任务--能力对象，在两个 PEP 提供恰当上下文，并把判定连接为可验证执行证据。当前结果仍不能用于给出 E2AG 与 AgentSpec、OAP、ToolGuardian 或 Agent libOS 的跨系统数值排名。
