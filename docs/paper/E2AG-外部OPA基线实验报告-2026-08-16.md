# E2AG 外部 OPA 工具边界基线实验报告（2026-08-16）

## 1. 目的与公平性口径

本实验检验 RuntimeGuard 的工具允许集判定是否可由独立公开策略引擎复现。基线采用官方 Open Policy Agent（OPA）v1.17.0，不调用 E2AG 判定代码。输入限定为冻结集中的 8 个 `tools/call`：4 个工具名属于任务允许集合，4 个在集合外。另 2 个非 `tools/call` 用例检验 MCP 方法中介，不属于 OPA-Tool 的输入对象，明确排除而不计错。

OPA-Tool 不是 AgentSpec、OAP 等 Agent 治理方法的替代复现，也不接收事件来源、任务状态和跨层证据。实验只比较工具边界的功能判定，不比较本地时延。

## 2. 可复核配置

- OPA：v1.17.0，Linux amd64 static 官方发布件；
- 上游与许可证：`https://github.com/open-policy-agent/opa`，Apache-2.0；
- 发布件 SHA-256：`e83da46804832578e9d9e1733dffbe4d3b5f8cc9c26eb124da9ceea4abfe189f`；
- OPA 发布件报告的构建标识：`64a3625d33bc6ad8e7c40df03b76ce2fb3ab4d21-dirty`；
- 冻结输入 SHA-256：`547173a48fe31944850f07e3311919424cd29a85cd7a658b0fb842ece7b99014`；
- Rego 策略 SHA-256：`ce4425a89d9859522188f376d5d353612cdaba35031a921b7f766a75397f7c4a`；
- 允许模式：`ledger.record_*`、`repo.read`、`mail.send`。

Rego 策略采用 default-deny：仅当方法为 `tools/call` 且工具名匹配允许模式时返回 allow。逐例运行、版本、哈希和排除原因保存在 `experiments/e2ag/results/opa_tool_baseline_summary.json`。

## 3. 结果

| 方法 | 集合内通过 | 集合外拒绝 | 总体判定一致 |
|---|---:|---:|---:|
| NoGuard | 4/4 | 0/4 | 4/8 |
| RuntimeGuard | 4/4 | 4/4 | 8/8 |
| OPA-Tool v1.17.0 | 4/4 | 4/4 | 8/8 |

OPA-Tool 与 RuntimeGuard 在该切片上功能等价。这说明当前工具名允许集结果不是内部测试桩特有行为；同一规则可以由独立通用策略引擎执行。该结果不说明 E2AG 在工具名判定上优于 OPA。

## 4. 对论文主张的影响

论文可以新增一个有限但真实的外部实现参照：工具边界的允许集语义具有独立实现一致性。E2AG 相对该基线的研究内容仍是跨对象授权闭合，即来源--类型契约、任务准入、任务作用域能力生命周期、双 PEP 完整中介和跨层执行证据。当前仍不能给出 E2AG 与 AgentSpec、OAP、ToolGuardian 或 Agent libOS 的跨系统数值排名。
