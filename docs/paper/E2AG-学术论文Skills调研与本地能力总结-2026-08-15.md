# E2AG 学术论文 Skills 调研与本地能力总结

日期：2026-08-15

## 1. 结论

社区没有统一的“五星评分”。skills.sh 的榜单主要依据匿名安装遥测，因此本次以安装量、仓库活跃度、技能边界、可验证工作流和安全审计作为代理指标。安装量高只说明流行，不等于适合中文计算机系统论文，也不等于内容与代码安全。

本项目不直接安装一个“自动写整篇论文”技能。更合适的组合是：审稿门控、LaTeX/PDF 定向审计、文献检索、实验设计与结果图审计，再叠加我们自己的中文系统论文逻辑和《软件学报》格式门禁。

## 2. 值得借鉴的社区 Skills

| Skill | 公开指标（检索时） | 值得借鉴 | 不直接采用的原因 |
|---|---:|---|---|
| `latex-paper-en` | skills.sh 约 4.5K installs；仓库约 402 stars | 对已有 LaTeX 稿件做模块化编译、格式、逻辑、摘要、算法和实验审计 | 主要面向英文会议/期刊，不能覆盖中文《软件学报》模板和本项目系统安全论证 |
| `paper-audit` | skills.sh/第三方索引约 1.4K--2.1K installs | 先审稿、分 blocker/major/minor、再给投稿门禁 | 第三方安全页面存在 marketplace warning；适合借鉴门禁思想，不宜未经代码审查直接安装 |
| `literature-review`（davila7） | 约 1.8K installs；仓库约 30K stars | 多数据库检索、主题综合、引用核验 | 依赖较重，偏通用系统综述；仓库 stars 不是单个 skill 的质量评分 |
| `literature-review`（affaan-m） | 约 1.4K installs；仓库约 236K stars | 强调检索、筛选、综合与引用支撑 | 巨型仓库的 stars 不能归因于该 skill；仍需逐条验证引用 |
| `figure-results-review` | 约 47 installs | 检查图、caption、baseline、误差线和正文主张是否一致 | 影响力较小，且偏机器学习结果图；其证据审计思想可复用 |
| `scientific-writing` | 约 58 installs | IMRaD、报告规范和投稿准备 | 偏泛化科学写作，无法解决系统架构、形式化作用和执行链实验问题 |
| `paper-creator` | 约 20 installs | 分节编译和测试驱动写作 | 公开安全审计出现失败/告警，不采用 |

最适合本项目的借鉴顺序为：`paper-audit` 的审稿门禁 → `latex-paper-en` 的定向模块 → `literature-review` 的检索核验 → `figure-results-review` 的证据对齐。不要使用通用“scientific-writing”直接生成整篇正文。

## 3. 我们自己的学术论文 Skills

### 3.1 `revise-systems-paper`（本次新增）

位置：`C:/Users/sugar/.codex/skills/revise-systems-paper/`

职责：把合作者意见转为可验证门禁，围绕研究问题、系统抽象、方法、算法、实验和期刊格式重构已有计算机系统/软件工程论文。

核心门禁：

1. 摘要不能把实验表格序列化成连续数字，只保留 1--2 个中心比较；
2. 引言必须由系统对象、信任边界、执行语义和失效机制推出研究缺口；
3. 问题定义先用自然语言概括系统、参与者、威胁、目标和边界，再引入符号；
4. 公式必须被性质、算法、实现规则或实验实际使用，否则删除；
5. 架构图表达组件、状态、控制所有权、接口和信任边界；时序流水线另画执行图；
6. 实验规模按 workload、connector、tool、model、system configuration、baseline、并发量和真实集成等独立维度衡量，重复次数不等于“上量”；
7. 编译成功不等于投稿格式合规，必须获取并核对当前官方模板。

配套参考：

- `references/review-gates.md`：把本轮评审转为 blocker/major/minor 门禁；
- `references/section-contracts.md`：摘要、引言、问题定义、方法和实验的章节契约；
- `references/experiment-evidence.md`：实验上量、baseline 公平性和证据层级；
- `references/venue-compliance.md`：《软件学报》等目标期刊格式审计。

### 3.3 与内置技能的组合

- `latex-tectonic`：编译 LaTeX，但不判断是否符合目标期刊模板；
- `pdf`：逐页渲染、字体和乱码验证；
- `documents`：后续生成并验证《软件学报》Word 投稿稿；
- `spreadsheets`：实验数据、独立复核表和数字一致性检查。

## 4. 本轮评审的处理含义

| 评审意见 | 当前判断 | 后续动作 |
|---|---|---|
| 摘要简单数字太多 | 成立 | 重写摘要，只保留中心效应，协议规模移入实验节 |
| 引言太短、太文科 | 成立 | 增加技术执行模型、授权错配机制、研究问题和设计要求 |
| 公式太简单、没意义 | 成立 | 建立公式用途追踪；删除装饰公式，补足能力传播和安全性质的非平凡定义 |
| 问题定义不概括 | 成立 | 先写五要素问题胶囊，再形式化 |
| 框架图是流水线 | 成立 | 新增架构图，保留或重画单独执行流程图 |
| 实验要上量 | 成立 | 不再仅增加 repeats；扩展 workload、connector、tool、model、baseline 和真实系统维度 |
| 格式不是软件学报 | 成立且是 blocker | 下载当前官方 Word 模板/样例，LaTeX 仅作为内容母稿，生成真正的投稿格式稿 |

## 5. 下一阶段入口

下一阶段应先取得《软件学报》当前模板并建立 Word 投稿骨架，同时冻结新的实验规模矩阵；在这两个 blocker 明确之前，不继续对现有 PDF 做表面润色。
